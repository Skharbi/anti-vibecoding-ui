## Admin users table review: Fail

I only read the code. `./data` (`useUsers`, `deleteUsers`) isn't in the repo, so I couldn't run the table, and I couldn't check loading, errors or how deletion behaves on the server. The whole component is `src/UsersTable.tsx` and `src/table.css`.

### Must-fix

**1. Delete can remove users you can't see**
Evidence: `UsersTable.tsx:10`, `:32`, `:19`. `selected` is kept when you change page, sort or filters.
Impact: tick "Select all" on page 1, go to page 2 and press Delete. The 25 users from page 1 are deleted, and nothing on screen shows they were still selected.
Fix: clear the selection whenever page, sort or filters change. Or keep it across pages on purpose and show "N selected across pages" next to Delete.

**2. Delete has no confirmation, no disabled state and no feedback**
Evidence: `:19`: `onClick={() => deleteUsers(selected)}`.
Impact:
- One click permanently deletes users.
- The button is active even when nothing is selected.
- Nothing shows while the delete is running, and failures are silent because the promise is never handled.
- Afterwards the rows stay on screen and stay selected, with no refetch.
Fix:
- Disable the button when `selected.length === 0`.
- Show the count on it ("Delete 3 users").
- Ask for confirmation in a dialog that names the users or the count.
- Show a pending state, then report success or the error.
- Clear the selection and refetch afterwards.
- Decide whether admins can delete their own account.

Also verify outside this code: the server must check permission for `deleteUsers`. This file shows no permission check, and hiding or disabling the button is not access control.

**3. The "Select all" checkbox doesn't track the selection**
Evidence: `:32`. The checkbox has no `checked` prop, so the browser keeps its state instead of React.
Impact:
- It stays ticked after you untick a row or change page.
- It never shows a partly-selected state.
- "Select all" only selects the 25 rows on this page, while the footer says `{total} users`.
Fix: set `checked` to "all rows on this page are selected", and set `indeterminate` through a ref when only some are. Rename it "Select all on this page", or offer a real "select all N matching users".

**4. Pagination goes out of range**
Evidence: `:45–47`, `:8`.
Impact:
- Prev can take you to page 0 or below.
- Next has no upper limit.
- Changing a filter keeps the current page, so filtering from page 5 usually shows a blank page.
Fix:
- Disable Prev at page 1, and Next at `Math.ceil(total / 25)`.
- Go back to page 1 whenever filters or sort change.
- Show "Page 2 of 14".

**5. Sorting and the table itself don't work with a keyboard or screen reader**
Evidence: `:31–43` use `<div>`s for the table. `:33–36` are sort headers that are just `<div onClick>`.
Impact:
- The column headers can't be focused or used from the keyboard.
- Screen readers get no table structure and no sort state.
- Nobody, sighted or not, can tell which column is sorted or in which direction.
Fix:
- Use `<table>`, `<thead>` and `<th scope="col">`.
- Put a `<button>` inside each sortable `<th>`.
- Add `aria-sort` on the sorted `<th>`, plus a visible up/down arrow.

**6. Checkboxes and filters have no labels**
Evidence:
- `:40`: the row checkboxes have no name.
- `:32`: "Select all" is loose text, not a `<label>`.
- `:23`, `:26`: the `<select>`s have no labels.
- `:18`: the Filters button doesn't say whether the panel is open.
Fix:
- Label each row checkbox, e.g. `aria-label={\`Select ${r.name}\`}`.
- Wrap "Select all" in a `<label>`.
- Add visible "Role" and "Status" labels.
- Add `aria-expanded` and `aria-controls` to Filters.

**7. The layout breaks on narrow screens and with long emails**
Evidence: `table.css:1` uses fixed columns totalling 920px, with no scroll container and no text wrapping.
Impact:
- On a phone or tablet the whole page scrolls sideways.
- Long emails spill into the Role column.
- The 140px checkbox column wastes space.
Fix:
- Wrap the table in a scroll container (`overflow-x: auto`).
- Use `minmax()` / `fr` column widths.
- Let emails wrap (`overflow-wrap: anywhere`), or truncate them with the full value in a `title`.
- Keep the Name column visible while scrolling (`position: sticky`).

### Should-fix

- **No loading, empty or error state** (`:38`). Nothing shows while data loads, an empty filter result looks like a broken table, and a failed request looks the same as no users.
- **Status can be filtered but isn't shown** (`:27` vs `:41`). You can't tell suspended users apart in the default list. Add a Status column with a text label, not just a colour.
- **Active filters disappear when the panel closes** (`:21`). Show them as removable chips, or a count on the button ("Filters (2)").
- **No search by name or email.** It's the most common admin task on this kind of screen. I rank it a strong should-fix, but it depends on what your product needs.
- **Values are shown raw** (`:41`). `lastActive` isn't formatted for the viewer's language and time zone, and roles are lowercase database values. Also, `{total} users` sits under the pager instead of next to it, and `sort.key` is typed as any `string`.
- **Page, sort and filters aren't in the URL**, so refreshing loses them and a link can't be shared.
- **The Delete button has no hover or focus style** (`table.css:3`). Its colour contrast is fine (roughly 5.6:1).

### What already passes

- Rows are keyed by `r.id`, not by array index.
- Sorting logic is correct: clicking a new column sorts ascending, clicking it again reverses.
- Filters use native `<select>`s, which are keyboard accessible once labelled.
- Destructive styling is used only on Delete.
- The page size is fixed at 25, so no huge list is rendered.
