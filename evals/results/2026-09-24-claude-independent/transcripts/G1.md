## final
I've built the dashboard as plain HTML, CSS and JS with no dependencies, as the repo README asks. The repo was empty with no product named, so I made one up to design around: **Ledgerline**, an invoicing app. The dashboard is a trial-funnel view for its growth team, and every figure is sample data, labeled as such on the page.

I rendered it in headless Chromium in light mode, dark mode and at phone width (390px). There were no console errors and no sideways scrolling. The empty state, the error banner and the chart hover all worked. The hosted preview didn't publish because the upload wasn't approved. Open `index.html` directly, or tell me to try publishing again.

**What's on the page**
- **Filters in one row:** last 7, 30 or 90 days, plus plan, region and channel. They apply to every panel and are remembered between visits.
- **Summary row:** new paid accounts as the headline figure, then trials started, activation rate, trial-to-paid and new MRR. Each one shows the change against the previous period and a one-line definition.
- **Daily trials and activations:** a line chart with a hover readout that also works with the arrow keys, weekend shading, and a "Show table" button with the full numbers.
- **First-week funnel:** five steps from starting a trial to getting paid by a client, with the biggest drop marked.
- **Acquisition channels:** a sortable table with a totals row. On phones it scrolls sideways inside its own box, with the channel names pinned.
- **Weekly cohort grid:** the share of each week's trials that sent an invoice in each following week. Cells that aren't measurable yet are left blank.

**How the numbers are defined**
- **Activation rate** only counts trials at least 7 days old. So the orange activation line stops 7 days before the last day shown, and the chart says why.
- **Trial-to-paid** divides paid accounts by trials whose 14-day trial ended in the period.
- **The cohort grid** always shows the 8 most recent complete weeks, so the date filter doesn't change it. The plan, region and channel filters do, and the panel says so.

**To see the other states**
- **Empty:** choose Plan "Practice" and Region "Asia-Pacific". In the sample data that plan isn't sold there, and the message says so.
- **Error:** add `#simulate-error` to the URL. If data was already loaded, it stays on screen with a "Try again" button.
- **Offline:** the dashboard retries on its own when the connection comes back.

To use real data, replace `fetchMetrics` in `app.js` with a call that returns the same shape. The README covers this and the states above.
