# Security review: admin projects UI

**Verdict: Fail.** The biggest risk is that the delete action has no confirmation and ignores errors. The second is that the admin check only runs in the browser, and nothing here shows the server repeating it.

I read all three files: `src/ProjectRow.tsx`, `src/api.ts` and `src/auth.ts`. `src/UserContext` is imported but isn't in the repo, so I couldn't check how the current user and role are loaded. Nothing was run. Everything below comes from reading the code only.

## Must-fix

**1. Only the browser checks that the user is an admin**
- **Evidence:** `src/ProjectRow.tsx:10`. The check `user.role === "admin"` only decides whether the button is shown.
- **Impact:** Any logged-in user can send `DELETE /api/projects/:id` directly, for example with curl or dev tools. Hiding the button doesn't stop them. If the server doesn't check the role, and that the user may act on that project, any user can delete any project.
- **Needs checking on the backend:** I can't confirm this from frontend code.
- **Fix:** The DELETE endpoint must check the admin role (and project access) from the server-side session. Don't rely on anything the client sends.
- **Verify:** Send the DELETE with a non-admin session cookie and expect a 403.

**2. Delete happens on one click, with no confirmation and no error handling**
- **Evidence:** `src/ProjectRow.tsx:11` and `src/api.ts:3`. The promise from `api.del` is thrown away. `fetch` doesn't fail on a 401, 403 or 500, so failures pass silently.
- **Impact:**
  - One misclick deletes a project for good.
  - A failed delete looks the same as a successful one.
  - The row doesn't disappear after a successful delete, so the admin will likely click again.
  - Nothing prevents double-clicks, so the DELETE can be sent twice.
- **Fix:**
  - Add a confirmation that names the project (for high-value data, have the user type its name).
  - Disable the button while the request is running.
  - Check `res.ok`, and show an error on failure.
  - Remove or refresh the row only after the server confirms.
  - Consider undo or soft delete.
- **Verify:** Force a 403 and a 500 and check that an error appears and the row stays. Double-click and check that only one request is sent.

## Should-fix

**3. The project ID goes into the URL without encoding**
- **Evidence:** `src/ProjectRow.tsx:11`, `` `/api/projects/${project.id}` ``.
- **Impact:** The browser resolves `../` in URLs. An ID like `../users/42` becomes `DELETE /api/users/42`, which hits a different endpoint with the admin's cookies. This only matters if IDs can ever be influenced by users or come from imported data, but the fix is one line.
- **Fix:** Use `encodeURIComponent(project.id)`.

**4. Cross-site request forgery (CSRF) protection isn't visible**
- **Evidence:** `src/api.ts:3`. The delete uses cookie auth (`credentials: "include"`) and sends no CSRF token.
- **Impact:** DELETE requests from another site need browser permission first, which helps. That only holds if the server's cross-origin (CORS) settings don't echo back any origin while allowing credentials, and if the cookies are set with `SameSite`.
- **Needs checking on the backend:**
  - The CORS allow-list.
  - `SameSite` / `Secure` / `HttpOnly` on the session cookie.
  - That there is no GET or POST route that also deletes projects.
- **Fix:** Add a CSRF token or check the request's `Origin` header on the server for state-changing requests.

**5. Missing user data or failed requests aren't handled safely**
- **Crash when no user is loaded:** `src/auth.ts:3` returns the context value unchecked. If no user is loaded (logged out, or the session is still loading), `user.role` at `ProjectRow.tsx:10` throws and the table crashes. It fails closed, which is safe, but it's still broken.
- **Error responses treated as data:** `src/api.ts:4` parses the response body as JSON without checking `r.ok`, so error responses get used as if they were real data.
- **Unset API URL:** at `src/api.ts:1`, if `VITE_API_URL` is unset, requests go to `"undefined/api/..."`.
- **Fix:** Guard against a missing user. Check `r.ok` in the API helper and throw on failure. Stop the app at startup if the API URL is missing.

**6. Every delete button has the same name**
- **Evidence:** `src/ProjectRow.tsx:11`. Every row's button reads just "Delete project".
- **Impact:** A screen-reader user moving between buttons can't tell which project a button deletes, which makes deleting the wrong one easier.
- **Fix:** Use `aria-label={`Delete project ${project.name}`}` or visually hidden text.

## What already passes
- **No cross-site scripting risk found:** `project.name` is rendered as normal JSX text, so React escapes it. There is no `dangerouslySetInnerHTML` or similar unsafe rendering.
- **No secrets in the code:** `VITE_API_URL` is a public base URL, not a secret. No tokens are kept in `localStorage`.
- **Session cookies stay out of JavaScript:** the app uses cookie sessions rather than bearer tokens readable from JavaScript.

- **Deployed app:** the security headers (content security policy and protection against being embedded in a frame).
