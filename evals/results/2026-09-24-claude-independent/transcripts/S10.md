# Review: `src/ProjectSettings.tsx`

**Result: Fail.** Two bugs need fixing before this ships. The page can show the delete button to users who shouldn't see it, and it can tell users a project was deleted when it wasn't.

Scope: I only read the code. The repo has no `package.json`, app shell or backend, so I couldn't render the page or test the API. Anything that depends on the server is marked as needing a check.

## Must-fix

**1. The delete button appears when the permission check fails**
Evidence: `src/ProjectSettings.tsx:11`: `.catch(() => setCanEdit(true))`. Line 9 also calls `r.json()` without checking `r.ok`. So a network error, or a 401/403/500 that returns an HTML page, makes `json()` throw, and the catch then shows the delete button.
Impact: a user without edit rights sees "Delete project" whenever the permission request fails. If the backend doesn't check authorization on `DELETE /api/projects/:id` itself, anyone can delete the project. Hiding the button isn't a security control, so the backend still needs to be checked either way.
Fix: when the check fails, keep the button hidden: `if (!r.ok) throw …`, and `.catch(() => setCanEdit(false))` plus an error state. Confirm the server returns 403 for users without permission.

**2. "Project deleted." appears before the delete happens, and failures are hidden**
Evidence: line 15 sets `deleted = true` before the request is sent. Lines 16–21 try three times, ignore every error (`catch {}`), and return quietly whether or not it worked.
Impact: the user is told the project is gone when the request may have failed (403, 409, 500, offline). They leave thinking it was deleted, and it wasn't. The loop also retries 4xx errors that will fail again, with no delay between attempts. And if the first delete worked but its response was lost, the retry gets a 404, which is treated as a failure.
Fix: track states `idle → deleting → deleted | error`. Show "Deleted" only after `r.ok`. Show the error with a retry button. Only retry network errors and 5xx, with backoff. Treat a 404 on a retry as success.

**3. No confirmation for a delete that can't be undone**
Evidence: line 28, one click calls `deleteProject`.
Impact: one misclick or stray Enter key deletes the project permanently. The page never shows which project will be deleted.
Fix: add a confirmation dialog that names the project and states what will be lost. For something this destructive, ask the user to type the project name. Or use a soft delete with an undo option.

## Should-fix

- **Loading, no-permission and error look the same.** `canEdit` starts as `false` (line 4), so the button pops in after the request, which shifts the layout. Users without permission get no explanation. Add loading and "You don't have permission to delete this project" states.
- **Stale response when `projectId` changes.** The effect at lines 7–12 never cancels its request, so a late reply for the previous project can set `canEdit` for the new one. Use an `AbortController` in the effect's cleanup.
- **Focus is lost and the result isn't announced.** Line 24 replaces the whole section, so the focused button disappears and focus falls to `<body>`. Screen readers aren't told the result. Put the result in `role="status"` (or `role="alert"` for errors) and move focus to it, or send the user to the project list.
- **No next step after deleting.** The user is left on a settings page for a project that no longer exists. Redirect them, or link back to the project list.
- **The delete button looks like any other button.** Line 28 uses a default `<button>`, so it doesn't look dangerous. Use the danger style from your design system, and put it in its own "Danger zone" section, apart from normal settings.
- **Hard-coded spacing values.** Lines 24, 26 and 27 use padding like `13px 21px` and `17px 23px`, `fontSize: 22` and `marginBottom: 7`. These don't match each other or any spacing scale. Use the app's design tokens or CSS classes.
- **`projectId` goes into the URL unescaped** (lines 8 and 18). Use `encodeURIComponent(projectId)` so a bad ID can't change the path.
