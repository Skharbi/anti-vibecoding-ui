## Fix first: no one can actually sign up

**[Must-fix] Keyboard users can't submit, and the "Sign up" button doesn't send anything**
- Evidence: `Signup.tsx:15`. "Sign up" is a `<div onClick>`, and there is no `<form>`. Its click handler only sets an error message; nothing gets submitted even when the email is valid.
- Impact: you can't Tab to it, Enter doesn't submit, and screen readers don't announce it as a button. For everyone else, clicking it with a valid email does nothing visible. Nobody can finish signing up.
- Fix: wrap the fields in `<form onSubmit>` and make the button `<button type="submit">`. Add a pending state that disables the button and shows "Creating account…". Add success handling (redirect or confirmation) and a server-error message the user can retry from.
- Verify: using only the keyboard, Tab to the email field, type an address, press Enter. The request should fire, the pending state should show, and success or error should appear.

`signup.css:4` makes this worse. `outline: none` on the input and CTA, with no replacement style, means keyboard users can't see where focus is. Fix this in the same change: use `:focus-visible { outline: 2px solid …; outline-offset: 2px }`.

## Next, in order

1. **[Must-fix] The terms modal isn't a real dialog** (`:14`, `:16–23`). "View terms" and "Close" are both `<div>`s, so the modal can't be opened or closed from the keyboard. Focus doesn't move into it or stay inside it, Escape doesn't close it, and it has no `role="dialog"` or accessible name. Use a native `<dialog>` with `showModal()`: it handles focus trapping and Escape. Make the trigger and Close into `<button>`s. On close, return focus to the trigger.
2. **[Must-fix] The label isn't linked to the input** (`:11–12`). `<label>Email</label>` has no `htmlFor`/`id`, so the field has no accessible name and clicking the label does nothing. Also add `type="email"`, `autoComplete="email"` and `required`.
3. **[Must-fix] Screen readers never hear the error** (`:13`). Add `aria-invalid` and `aria-describedby` pointing at the error, and `role="alert"` (or move focus to the field) when you submit. The error also stays up after the user fixes the email; clear it on change or re-check on blur. `email.includes("@")` is a very weak check. It's fine as a hint, but the server must do the real validation.
4. **[Should-fix] There's no terms consent.** The `terms` state only tracks whether the modal is open. If users have to accept the terms, add a real checkbox that's included in the submit. If they don't, ask legal what wording to put under the button (e.g. "By signing up you agree to…").
5. **[Should-fix] The input border is too faint** (`signup.css:3`). `#ddd` on white is about 1.4:1, and WCAG 1.4.11 asks for 3:1 for input boundaries. Use something around `#8a8a8a` or darker.
6. **[Should-fix] The modal is cramped on phones** (`signup.css:8–9`). The backdrop has no padding, so the modal touches the screen edges at 375px. Add `padding: 16px` to the backdrop and `width: 100%` to the modal.
7. **[Should-fix] Semantics:** the `.h` titles are `<div>`s; make them `<h1>` and `<h2>`. The form has no password field or auth method either. If this is a magic-link flow, say so ("We'll email you a sign-in link").
