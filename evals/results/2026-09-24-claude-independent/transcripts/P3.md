## Must-fix

**1. The page tells search engines not to index it**
Evidence: `app/pricing/layout.tsx:2` has `robots: { index: false, follow: false }`.
Impact: The README says `/pricing` is a public page people should find through search. This setting keeps it out of search results entirely, and `follow: false` also stops crawlers following its links to Features, Customers and Docs.
Fix: Remove the `robots` setting, or set it to `{ index: true, follow: true }`.
Verify: The rendered HTML has no `noindex` meta tag, and Search Console's URL inspection reports the page as "indexable."

**2. Prices only exist after the browser runs JavaScript**
Evidence: `page.tsx:1` makes the whole page run in the browser (`"use client"`), and `page.tsx:8` loads the plans with a `fetch` inside `useEffect`.
Impact: The HTML the server sends has a heading and nothing else. Crawlers, link previews and anyone with slow or blocked JS see a pricing page with no prices, which also undoes fix #1. Real visitors see a blank area, then the content appears and the layout jumps.
Fix: Turn it into a server component and load the plans on the server. Use `revalidate` so prices can change without a redeploy. If the plans come from your own backend, read that data source directly instead of calling your own API route.
Verify: Run `curl -s <url>/pricing | grep <plan name>` and check the prices are in the raw HTML.

**3. Nav links can't be reached by keyboard or followed by crawlers**
Evidence: `page.tsx:13-15` uses `<span onClick={() => router.push(...)}>`.
Impact: These can't be tabbed to or activated with a keyboard, screen readers don't announce them as links, and middle-click or "open in new tab" doesn't work. Crawlers also can't discover `/features`, `/customers` or `/docs` from this page. This fails WCAG 2.1.1 (keyboard access) and 4.1.2 (name, role, value).
Fix: Replace them with `<Link href="/features">` from `next/link`. Then `useRouter` and `"use client"` are no longer needed.
Verify: Tab through the page: each link gets a visible focus ring and opens with Enter.

**4. A failed load shows an empty page with no message**
Evidence: `page.tsx:8` doesn't check `r.ok`, has no `.catch`, and shows nothing while loading.
Impact: If `/api/plans` returns an error, the page either stays empty or crashes with `plans.map is not a function`. Visitors get no feedback and nothing to retry. Fixing #2 removes most of this, but the server version still needs an error boundary or a fallback.

## Should-fix

- **The page title is "App"** (`layout.tsx:2`), which is what shows in search results and browser tabs. Use something like "Pricing – Tallyline" and add a `description` and a canonical URL.
- **There's no way to sign up.** No plan has a call-to-action, so the page's main job (choosing a plan and starting) has no next step.
- **Prices have no context.** `price` is a plain string, so the page can't show billing period, currency, tax, trial terms or the difference between annual and monthly. Make sure the API's strings include these, or structure the data.
- **Nothing on the page says what the product is.** Apart from plan names, there's nothing about bookkeeping for independent cafés. Plan names from the API may be the only thing identifying the product, and nothing highlights a recommended plan or compares plans. Swap the logo and this could be anyone's pricing page.
- **The heading comes before the nav** (`page.tsx:11-12`), and the nav has no label. Normally site nav belongs in a shared header above the `<h1>`.
- **Feature list keys use the feature text** (`page.tsx:18`). If two features have the same text, React will warn and may render the list wrongly.
