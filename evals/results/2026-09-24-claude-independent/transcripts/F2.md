## final
I reviewed `src/PriorityQueue.tsx` and `src/queue.css` by reading the code only. There's no `package.json`, no tests and no harness, so I couldn't render it or try it with a keyboard or screen reader. Everything below comes from reading the code.

**Verdict: Fail.** One must-fix: after a move, a screen reader user usually hears nothing.

## Must-fix

**1. Most moves are never announced to screen reader users**
- **Evidence:** `PriorityQueue.tsx:27`. The status message only reads `"${items[0].title} is now first"`, so it only changes when the top item changes.
- **Impact:** Moving an item from position 6 to 5 leaves the status text the same, so a screen reader says nothing. The 180ms slide is the only sign the action worked, and screen reader users can't see it. Worse, the message says the wrong thing: users need to know where their item went, not what's at the top. It also fires when the parent reloads data and the top item changes, even though the user did nothing.
- **Fix:** Announce the action itself, not something computed from `items`. For example, keep the text in state and set it in the click handler: `"${title} moved to position 5 of 12"`. Having the parent return the new index from `onBump` is the cleanest way to get that number.
- **Verify:** With VoiceOver or NVDA, move an item in the middle of the list and confirm you hear its new position.

## Should-fix

**2. Every button has the same name, "Move up"** (`:34`)
In a screen reader's list of buttons, or with voice control ("click Move up"), N identical buttons can't be told apart. Include the item in the name: `aria-label={`Move ${it.title} up`}`, or add a visually hidden span.

**3. The top item's button still shows but does nothing** (`:34`)
The top row has a "Move up" button that has nothing to move up. **Careful with the fix:** if you use `disabled={i === 0}`, a keyboard user who bumps an item into first place is focusing a button that just became disabled. Focus then drops to `<body>`. Use `aria-disabled="true"` plus a guard in the handler, or move focus on purpose.

Good news on focus: when an item moves up, React's keyed reordering moves the neighbouring row in the DOM, not the one that was bumped. So focus should stay on the bumped item's button. That's inferred from the code, not tested.

**4. The slide animation measures positions the wrong way** (`:15`, `:17–20`)
- `getBoundingClientRect().top` is measured against the browser window, not the list. If the user scrolls, or anything above the list changes size between renders, every row animates by the scroll distance on the next update, including a change that only touches a score.
- Rapid clicks: the new position is measured while the previous 180ms animation is still running. The in-flight transform is included in the measurement, so the next animation starts from the wrong place and rows jump.
- Rows that are removed are never deleted from the `positions` map. If one comes back later, it animates from wherever it used to be.
- **Fix:** Measure `el.offsetTop` relative to the list. Call `el.getAnimations().forEach(a => a.cancel())` before measuring. Remove ids that are no longer in the list. Also do all the measuring first and start all the animations afterwards, which avoids repeated forced layout on long lists.

**5. The layout breaks with long titles and 3-digit ranks** (`queue.css:2`)
- `1fr` won't shrink below the longest word, so a long unbroken title (a URL or ID) causes horizontal scrolling on narrow screens. Use `minmax(0, 1fr)` together with `overflow-wrap: anywhere` on `.title`.
- The `2ch` rank column overflows from rank 100 onward. Use `auto`, or `3ch` or wider with `font-variant-numeric: tabular-nums`.
- At 320px wide, the score and button columns leave the title about 100px. Consider stacking the score under the title on narrow screens.

**6. An empty queue shows nothing** (`:28`)
With `items = []` you get the heading above an empty `<ol>`. Show a line like "No items in the queue."

**7. Hard-coded ids** (`:25`, `:27`)
`pq-h` and `pq-status` will clash if the component is rendered twice, and `aria-labelledby` would then point at the wrong heading. Use `useId()`. `pq-status` isn't referenced anywhere, so that id can simply be removed.

**8. Button behaviour details** (`:34`)
- There's no `type="button"`, so if the component ends up inside a `<form>`, clicking it submits the form.
- There's no pending or error state. If `onBump` saves to a server, a failed save leaves the order the user saw out of step with what was saved, and nothing tells them.

## Minor
- `queue.css:6`: a global `*` rule in a component stylesheet affects the whole app, and does nothing for this component (the animation already checks reduced motion in JS). Remove it.
- `queue.css:5`: the `.sr-only` class is missing `margin:-1px; padding:0; border:0`, and uses the deprecated `clip`. Add `clip-path: inset(50%)`.
- The focus colour `#0b57d0` and border `#ddd` are hard-coded instead of using design tokens. The button is an unstyled browser default, so it probably won't match the rest of the app.
- The strings ("Score", "Move up", "is now first") are hard-coded English, and the score isn't locale-formatted.

## What already works
- The HTML structure is right: a `<section>` labelled by its heading, an `<ol>` for an ordered list, a real `<button>`, and a `role="status"` region that exists before its text changes.
- Rows use `key={it.id}` rather than the index, which is what keeps focus on the moved item.
- The animation checks `prefers-reduced-motion`, still records positions when motion is reduced, and animates only `transform`.
- 40px buttons pass WCAG 2.5.8's 24px minimum target size. There's a visible `:focus-visible` outline with an offset.
- The rank is shown as text, so it doesn't depend on list markers. That matters because `list-style: none` removes list semantics in Safari/VoiceOver.

## Needs your input
- **Score vs. rank:** Is the queue sorted by score, or ordered by hand? If "Move up" doesn't change the score, a lower-scored item can sit above a higher one and users won't know which to trust. If the order is manual, the score may not belong on the row.
- **Moving down:** There's only "Move up". Moving an item down means bumping each item below it one at a time. Decide whether you need "Move down" or "Move to top".
- **Visual identity:** The rows are generic: a divider, a number and a browser-default button. Nothing shows urgency or the triage context yet. That's worth a design pass once the behaviour is fixed.
