**Result: Fail.** One problem blocks the component's main job: Rename and Delete can only be reached by people using a mouse.

## Must-fix

**1. Rename and Delete only exist while a mouse is hovering over the row**
- **Evidence:** `filelist.css:3-4`. `.row-actions { display: none }` is only changed to `flex` by `tr:hover`.
- **Impact:** `display: none` takes the buttons out of the tab order and hides them from screen readers. So:
  - **Keyboard users** can't reach Rename or Delete at all.
  - **Screen-reader users** hear an "Actions" column that is always empty.
  - **Touch users** have no hover. Some mobile browsers fake a hover on tap and some don't, so on phones the actions are unreliable at best.
  - **Mouse users** also see the row change height when the buttons appear, because the buttons are taller than the text.
- **Fix:** keep the buttons in the layout and always visible. If showing them only on hover is a firm design choice, fade them instead of removing them, and show them whenever the row has keyboard focus or the device has no hover:
  ```css
  .row-actions { display: flex; gap: 8px; }
  @media (hover: hover) and (pointer: fine) {
    .row-actions { opacity: 0; }
    .files tr:hover .row-actions,
    .files tr:focus-within .row-actions { opacity: 1; }
  }
  ```
- **Verify:** tab through the table and confirm each button gets focus with a visible outline. Check that the buttons appear on a touch viewport, and that a screen reader announces them.

## Should-fix

**2. The button names don't say which file they act on**
- **Evidence:** `FileList.tsx:12-13`.
- **Impact:** a screen reader's list of buttons reads "Rename, Delete, Rename, Delete…" with no file names. For Delete, that makes it easy to remove the wrong file.
- **Fix:** add `aria-label={`Delete ${f.name}`}`, and the same for Rename. You can also put the file name in visually hidden text inside the button instead.

**3. Nothing guards against an accidental delete, and nothing shows progress**
- **Evidence:** `FileList.tsx:13` calls `onDelete(f.id)` straight away. There's no confirmation, no undo, and no pending or error state for each row.
- **Impact:** it depends on the parent component. If the parent deletes immediately, one misclick loses a file. With no pending state, clicking twice sends two requests.
- **Fix:** either document that the parent must confirm or offer undo, or add a `pendingId`/`busy` prop that disables the row's buttons and shows progress. Report failures through a live region.
- **Needs checking:** the code that calls `onDelete`.

**4. The buttons don't have `type="button"`**
- **Evidence:** `FileList.tsx:12-13`.
- **Impact:** if this table is ever placed inside a `<form>`, clicking Rename or Delete will submit the form.
- **Fix:** add `type="button"` to both buttons.

**5. An empty list shows nothing useful**
- **Evidence:** `FileList.tsx:8`. When `files` is `[]`, you get a table header with no rows under it.
- **Fix:** show a message row such as "No files yet", or render a proper empty state instead of the table.

**6. Long file names break the layout on narrow screens**
- **Evidence:** `filelist.css:2` has no wrapping rules, and the table has no scroll container.
- **Impact:** a name with no spaces, like `quarterly_report_final_v3_REVISED.xlsx`, forces the table wider than a phone screen. The whole page then scrolls sideways and the action column is pushed off-screen.
- **Fix:** put `overflow-wrap: anywhere` on the name cell, keep the size column narrow with `white-space: nowrap`, and wrap the table in a horizontal scroll container that can take keyboard focus. Test with long names at 320px wide.

**7. The `.sr-only` utility is missing parts of the standard pattern**
- **Evidence:** `filelist.css:5` has no `white-space: nowrap`, `margin: -1px`, `padding: 0` or `border: 0`, and uses only the deprecated `clip`.
- **Impact:** in some browsers the hidden text can wrap or take up space. If the project already has an sr-only utility, use that one instead.

**8. The size column is hard to compare**
- **Evidence:** `size` is a preformatted `string` (`FileList.tsx:2`) and is left-aligned.
- **Impact:** sizes are hard to scan against each other, and the list can't be sorted by size later.
- **Fix:** right-align the column and use `font-variant-numeric: tabular-nums`. Taking bytes as a number and formatting them in the component would make sorting possible.
