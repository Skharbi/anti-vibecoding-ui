## Must-fix

**1. The Upgrade button has no visible keyboard focus**
Evidence: `app/billing/page.tsx:7`: `focus:outline-none` with no ring to replace it.
Impact: keyboard users can't see when this button, the main action on the page, is focused. This fails WCAG 2.4.7.
Fix: use `<Button>`. It already has a `focus-visible:ring-2`.

**2. Two imported files aren't in the repo**
Evidence: `components/ui/button.tsx:3` imports `@/lib/utils` (`cn`), and `app/projects/page.tsx:2` imports `@/components/ui/card`. Neither file exists.
Impact: if they aren't provided somewhere else, the build fails.
Fix: add the shadcn `cn` helper and the `Card` component, or check where they're supposed to come from.

## Should-fix: consistency

**3. Four different primary button styles, three of them written by hand**

| Location | Colour | Radius | Size / type |
|---|---|---|---|
| `Button` default (`button.tsx:10,15`) | `bg-primary` (dark navy) | `rounded-md` (6px) | `h-10 px-4`, `text-sm font-medium` |
| Projects "New project" (`projects/page.tsx:9`) | `bg-blue-600` | `rounded-xl` | `px-5 py-2.5`, default font |
| Billing "Upgrade" (`billing/page.tsx:7`) | `bg-[#2563eb]` (the same blue as `blue-600`, but typed as a hex value) | `rounded-lg` | `px-4 py-2`, default font |
| Settings "Delete" (`settings/page.tsx:9`) | `bg-red-500` | `rounded-full` | `px-4 py-2`, default font |

- Your primary token is dark navy, but two pages use blue for their main action. Users see a different colour for "primary" depending on the page.
- `--destructive` (`0 84.2% 60.2%`) is effectively `red-500` already, so Delete can use `variant="destructive"` without any visual change.
- The Projects page puts a blue "New project" button next to a navy "Open" button (`projects/page.tsx:9` vs `:13`), so two primary styles show up on one screen.

Fix: replace all three raw buttons with `<Button>` / `<Button variant="destructive">`. If the product colour is really blue, change `--primary` instead of hardcoding it on each page.

**4. Rounded-corner overrides bypass the `--radius` token**
Evidence: buttons use `rounded-md`, `-lg`, `-xl` and `-full`. `settings/page.tsx:10` overrides the shared `Button` with `rounded-full`. Surfaces use `rounded-2xl` (`projects:11`), `rounded-lg` (`settings:7`) and `rounded-3xl` (`billing:5`).
Fix: remove the `rounded-*` overrides and let `--radius` control corners.

**5. Three different ways to draw a panel**
The panels are `<Card>` (Projects), a plain `<section className="border rounded-lg p-5">` (Settings), and a plain `<div className="rounded-3xl border p-6 shadow-lg">` (Billing, the only one with a shadow).
Fix: use `Card` everywhere.

**6. Page headers don't match**
Padding is `p-6` on Projects and Billing and `p-8` on Settings. The title is `text-2xl font-semibold` on two pages and `text-3xl font-bold` on Settings (`settings/page.tsx:5-6`). The gap below the header is `mt-6` on two pages and `mt-4` on Settings.
Fix: pick one set of values. A small `PageHeader` component (title plus an optional action) would keep them consistent.

**7. `Button` uses tokens that aren't defined**
Evidence: `button.tsx` uses `ring-ring`, `border-input`, `bg-background`, `bg-accent` and `text-accent-foreground`, but `tailwind.config.ts` and `globals.css` only define `primary` and `destructive`.
Impact: the `outline` and `ghost` variants probably show no hover feedback, and the focus ring falls back to Tailwind's default blue. The Settings Cancel button uses `outline`, so it's affected.
Also: `tailwind.config.ts` has no `content` array. On Tailwind v3 that means no utilities are generated at all. I couldn't check which Tailwind version you use because there's no `package.json`.
Fix: add the missing `--ring`, `--input`, `--background`, `--accent` and `--muted-foreground` variables and map them in the config.

**8. Colours hardcoded instead of tokens**
`text-gray-500` (`billing:6`), `bg-blue-600`, `bg-[#2563eb]` and `bg-red-500` are all written directly. Any theme change or future dark mode will skip them.

**9. Button states differ from page to page**
None of the three raw buttons has a disabled state. "Delete workspace" and "Upgrade" also have no hover state; "New project" is the only one with a hover (`hover:bg-blue-700`). Moving to `<Button>` fixes all of this.

**10. The Danger zone layout has gaps**
Evidence: `settings/page.tsx:8-10`. There's no spacing between the heading and the buttons, or between Delete and Cancel.
Also, a "Cancel" button in a danger zone has nothing to cancel. Usually it belongs in the confirmation dialog.
Needs checking: neither button has an `onClick` yet. When the Delete action is wired up, make sure it asks for confirmation and names the workspace being deleted.
