## Must-fix

**1. The structured data contains made-up and incorrect claims**
Evidence: `app/products/[slug]/page.tsx:10-14`
- The 4.9 rating from 1,284 reviews and the "Verified buyer" 5-star review are hardcoded. Every product gets the same numbers, and none of them appear on the page.
- `availability` is always `InStock`, even though `Product.inStock` exists (`lib/products.ts:1`).
- The "Launch week sale" is marked up as an `Event`. Google doesn't accept sales as events, the markup has no location, and the sale isn't shown on the page.

Impact: search results would show ratings and stock status that aren't real. That can get the site a manual action from Google and may count as misleading advertising under consumer law.
Fix: remove `aggregateRating`, `review` and `eventLd` until real review data exists and is shown on the page. Set `availability` from `p.inStock` (`InStock` or `OutOfStock`).

**2. Product data can inject script into the page**
Evidence: `page.tsx:17-18`. `JSON.stringify` doesn't escape `<`, so a name like `</script><script>…` from the API closes the tag and runs whatever follows.
Impact: anyone who can write product data (admin panel, supplier feed, a compromised API) can run script on your origin.
Fix: `JSON.stringify(jsonLd).replace(/</g, "\\u003c")`.
Verify: set a product name to `</script><script>alert(1)</script>` and confirm nothing runs.

**3. "Add to cart" does nothing**
Evidence: `page.tsx:23`. It's a bare `<button>` in a server component, with no handler, form or server action.
Impact: nobody can complete the page's main task. The button also stays active when the product is out of stock.
Fix: use a `<form action={addToCart}>` with a hidden `slug` so it works without JavaScript, or a client component. Add pending, success and error states, with the result announced through `aria-live`. Disable the button and say "Out of stock" when `!p.inStock`. The server must check stock again, because the page can be up to 10 minutes old.

**4. Missing products and failed requests aren't handled**
Evidence: `lib/products.ts:2`. `r.ok` is never checked, so a 404 or 500 response body gets parsed as a `Product`.
Impact: an unknown slug returns HTTP 200 with an empty title, a broken image and "€undefined". Search engines index these as real pages.
Fix: if `r.status === 404`, call `notFound()`. For any other non-OK response, throw and add an `error.tsx` so the user sees an error page with a retry. It's also worth checking the response shape before using it.

## Should-fix

5. **The slug isn't encoded before it goes into the URL** (`lib/products.ts:2`). A slug that decodes to `../` could make the server request a different API path. Use `encodeURIComponent(slug)` and require `process.env.API` to be set. As written, a missing value fetches `undefined/products/...` without any error.
6. **`params` is read synchronously** (`page.tsx:3-4`). In Next 15+, `params` is a Promise, so this logs a warning in 15 and breaks in 16. Use `const { slug } = await params;`. I couldn't confirm your Next.js version without a `package.json`.
7. **There are no page metadata.** There's no `generateMetadata`, so every product page has the same default title and no description, canonical URL or Open Graph image. That matters on a page meant to be found in search.
8. **The image** (`page.tsx:20`) is a plain `<img>` with a fixed 800×800 size. Without CSS it overflows on narrow phones, it's forced square, and it has no `sizes` or `priority`, so it loads slowly for what's probably the page's main image. Use `next/image` with `sizes` and `priority`. Also, `alt={p.name}` just repeats the heading. Describe the photo instead (e.g. "Front view, charcoal colorway"), or use `alt=""` if the image adds nothing.
9. **The price display** (`page.tsx:10,22`) hardcodes `€` and `EUR` and uses the API string as-is, so "12.5" shows as "€12.5". Format it with `Intl.NumberFormat(locale, { style: "currency", currency })`. If you sell to consumers in the EU, confirm that the price includes VAT and say so.
