- Evidence (Confirmed): `index.html:1` hardcodes the text, and there is no script, fetch or template.
- Impact: Users can never see items. There is no loading state, error state, or explanation of why the list is empty.
- Whether this is a defect depends on the product. It could be an intentional placeholder, so I'm not calling it must-fix.
- Fix: Once a data source exists, render distinct loading, empty, error and populated states. The empty state should say what an item is and give the next action, such as "No items yet. Create your first item", if the user can create one.
- Verify: Exercise each state with mocked responses.

**[Should-fix] No `<meta charset>` in the markup**
- Evidence (Confirmed): `index.html:1` has no charset declaration. Whether the server sends one in its `Content-Type` header is unknown (Needs verification).
- Impact: The current text is ASCII, so there is no visible effect today. Any non-ASCII content added later could be mis-decoded.
- Fix: Add `<meta charset="utf-8">` as the first element in `<head>`.
- Verify: Check the response headers and render some non-ASCII text.

**[Should-fix] Generic `<title>`, no meta description**
- Evidence (Confirmed): `<title>Items</title>`, and no description.
- Impact: This matters only if the page is public or appears in tabs and history, which I can't tell. "Items" doesn't identify the product or the page among other tabs.
- Fix: Use a specific title, such as "Items – <Product>", and add a description if the page is public.

**[Should-fix, minor] Viewport meta is incomplete**
- Evidence (Confirmed): `width=device-width` has no `initial-scale=1`.
- Impact: Modern browsers mostly handle this, and zoom is not blocked, which is good. Adding the attribute is harmless.
