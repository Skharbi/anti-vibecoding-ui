## Final output

The dialog doesn't trap focus in the usual sense. The problem is that it doesn't manage focus at all, so keyboard users end up stranded behind it. The code is in `src/ConfirmModal.tsx` and `src/modal.css`. I only read it and haven't run it.

## Causes

1. **The controls aren't focusable.** Cancel and Archive are `<div className="btn">` (`ConfirmModal.tsx:15-16`), and the close control is a `<span>` (`:18`). None has a `tabindex` or a key handler, so Tab never reaches them, and Enter and Space do nothing. A keyboard user cannot confirm or cancel from inside the dialog.

2. **Focus never moves into the dialog.** When it opens, focus stays on the "Archive project" button underneath the overlay. The next Tab goes to whatever follows in the page. The user can't see where focus is, and the dialog stays on screen.

3. **Nothing contains focus or blocks the background.** There is no focus trap, no `inert` or `aria-hidden` on the rest of the page, and no `role="dialog"` or `aria-modal`. Focus moves through the page behind the overlay, so the dialog is visible but unreachable.

4. **There is no Escape handler.** The only keyboard-independent ways to dismiss it are a mouse click on the overlay or on the ✕.

5. **The focus indicator is removed.** `.btn:focus, .close:focus { outline: none; }` (`modal.css:5`) would hide focus even if the elements were made focusable. Nothing replaces the outline.

6. **Focus isn't restored on close.** The trigger is unmounted from nothing, so focus is fine in this case. But the dialog is removed and the code doesn't set focus back to the trigger. Some browsers drop focus to `<body>` when the focused element is removed, so this is worth fixing.

7. **The dialog has no accessible name.** The title is a plain `div`, so screen readers don't announce it.

## Fix

The simplest option is the native `<dialog>` element with `showModal()`. It provides focus containment, `inert` background, Escape handling and top-layer rendering, and it restores focus on close.

```tsx
import { useEffect, useRef, useState } from "react";
import "./modal.css";

export function ArchiveProject({ onArchive }: { onArchive: () => void }) {
  const [open, setOpen] = useState(false);
  const ref = useRef<HTMLDialogElement>(null);

  useEffect(() => {
    const d = ref.current;
    if (!d) return;
    if (open && !d.open) d.showModal();
    if (!open && d.open) d.close();
  }, [open]);

  return (
    <>
      <button onClick={() => setOpen(true)}>Archive project</button>
      <dialog
        ref={ref}
        className="modal"
        aria-labelledby="archive-title"
        onClose={() => setOpen(false)}  // fires on Esc too
        onClick={(e) => e.target === ref.current && setOpen(false)} // backdrop click
      >
        <h2 id="archive-title" className="modal-title">Archive this project?</h2>
        <p>Members will lose edit access. You can restore it within 30 days.</p>
        <div className="actions">
          <button type="button" autoFocus onClick={() => setOpen(false)}>Cancel</button>
          <button type="button" className="primary"
                  onClick={() => { onArchive(); setOpen(false); }}>Archive</button>
        </div>
        <button type="button" className="close" aria-label="Close"
                onClick={() => setOpen(false)}>✕</button>
      </dialog>
    </>
  );
}
```

CSS changes:
- Remove the `.overlay` rule and use `.modal::backdrop { background: rgba(0,0,0,.45); }`.
- Delete the `outline: none` rule. Add `:focus-visible { outline: 2px solid #0b57d0; outline-offset: 2px; }`.
- Style `.btn` as a `button` and add `max-width: calc(100vw - 32px)` so it fits narrow screens.

Two details to keep:
- **Initial focus:** `autoFocus` goes on Cancel because this action is destructive-ish. That is a deliberate choice.
- **Always render the `<dialog>`:** keeping it mounted lets `showModal()` and `close()` work and restore focus to the trigger. The `{open && ...}` conditional in the original would prevent that.
