## Must-fix

**[Must-fix] Reordering is announced only when it changes the first item**
Evidence: `PriorityQueue.tsx:27`. The only live region reads `${items[0].title} is now first`.
Impact: moving item 4 to position 3 gives screen-reader users no feedback at all. When the first item does change, the message doesn't say which item the user acted on. It also says "is now first" on initial render and on any data refresh.
Fix: have the status describe the user's action, for example "Fix login bug moved to position 3 of 8". Set it from the bump handler or from a diff of the previous and next order, not from `items[0]`. Keep the region mounted and don't announce on first render.
Verify: with NVDA or VoiceOver, press "Move up" on rows 2 to 4 and confirm each move is announced once.

## Should-fix

**[Should-fix] Every button is named "Move up"** (`:34`)
Evidence: all rows render the same label with no item context.
Impact: in a buttons list or by Tab alone, users hear "Move up" repeated with no way to tell which item each one affects.
Fix: add `aria-label={`Move up ${it.title}`}`. The visible text "Move up" is contained in that name, so label-in-name (WCAG 2.5.3) still holds.

**[Should-fix] The first row's "Move up" is live but can't do anything** (`:34`)
Evidence: there is no `i === 0` handling.
Impact: it is a control that is either a no-op or misleading. I also can't tell whether `onBump` actually moves the item or only raises its score, so the "Move up" label may promise something the data doesn't deliver.
Fix: use native `disabled` on the first row, or make the label match what `onBump` does.

**[Should-fix] The FLIP animation measures the wrong positions** (`:15-20`)
Evidence:
- `getBoundingClientRect().top` is viewport-relative, so any scroll between renders makes `prev !== top` for every row and animates them all.
- It also includes the transform of any animation still running, so rapid clicks record a mid-flight position and the rows jitter.
- Positions for removed ids stay in the `Map` forever.

Fix: measure with `el.offsetTop` (layout position, unaffected by scroll or transforms). Prune the map to the current ids on each pass. Optionally cancel running animations before measuring.

**[Should-fix] No empty state** (`:26-37`)
Evidence: with `items=[]` the component renders the heading, an empty `<ol>` and a blank status.
Fix: render a message such as "No items to triage."

**[Should-fix] Narrow-width layout has no strategy, and long titles can break it** (`queue.css:2`)
Evidence: the grid is `2ch 1fr auto auto` with no `min-width: 0` on the title and no breakpoint.
Impact: a long unbroken title can push the score and button out of the row. Likely, but not verified by rendering.
Fix: add `.title { min-width: 0; overflow-wrap: anywhere }`. Below roughly 480px, stack the score under the title.

**[Should-fix] No feedback while `onBump` is pending or after it fails** (`:34`)
Evidence: the handler is fire-and-forget. If it is async, double clicks can send duplicate bumps and errors are silent.
Fix: only needed if `onBump` hits a server. Then add a pending state on the button and an error message.

## Needs verification
