## Final output

I rewrote the modal in `src/ConfirmModal.tsx` and `src/modal.css`. I haven't run it in a browser or tested it with a screen reader.

**Why keyboard users got stuck**
- **Not real buttons:** Cancel, Archive and ✕ were `div`/`span` elements with click handlers. They couldn't be reached with Tab or activated with Enter or Space.
- **No focus outline:** the CSS set `outline: none` on them, so even where focus landed you couldn't see it.
- **No focus handling:** focus never moved into the modal, nothing kept it inside, and it didn't return to the trigger on close.
- **No Escape:** pressing Escape did nothing.
- **No dialog semantics:** there was no dialog role or accessible name, and the page behind stayed interactive.

**What I changed**
- **Native dialog:** the overlay `div` is now a native `<dialog>` opened with `showModal()`. The browser then handles the focus trap, Escape, an inert background, and returning focus to the trigger.
- **Real buttons:** Cancel, Archive and ✕ are now `<button type="button">`, and the ✕ has `aria-label="Close"`.
- **Initial focus:** Cancel gets focus when the modal opens, which is the safer default for an archive action.
- **Dialog name:** the title is an `<h2>` and the dialog is labelled by it and described by the paragraph.
- **Backdrop click:** clicking the backdrop still closes the modal.
- **Focus outlines:** `outline: none` is gone. Buttons now show a `:focus-visible` outline.
- **Small screens:** the width is now `min(420px, 100vw - 32px)` with a max height and scrolling, so it fits narrow and short viewports.

**Things to check**
- The `open` state is gone, since the dialog element tracks that itself. If other code relied on it, tell me.
- Native `<dialog>` works in all current browsers. If you support older ones, say so and I'll look at a polyfill.
- Tab through it once: the trigger should open the modal, Tab should stay inside it, and Escape should close it and return focus to "Archive project".
