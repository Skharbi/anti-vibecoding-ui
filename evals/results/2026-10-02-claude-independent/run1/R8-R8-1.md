## Must-fix

**[Must-fix] Delete workspace has no confirmation and sits next to Cancel with no spacing or separation**
Evidence: `app/settings/page.tsx:9-10`. Both buttons are in one section with no wrapper, gap or handler.
Impact: A destructive action has no confirmation step and no stated consequence. The raw `<button>` and the `Button` have different shapes and sizes, so the pair looks mismatched. `Cancel` has nothing to cancel.
Fix: Use `<Button variant="destructive">` and wrap the pair in a `flex gap-2` container. Add a one-line consequence description. Put a confirm dialog on the delete action, ideally requiring the workspace name to be typed. Drop `Cancel` unless it lives in that dialog.
Verify: Tab to the button, confirm the dialog opens and focus is managed, and confirm Esc cancels.

**[Must-fix] Billing "Upgrade" removes the focus indicator**
Evidence: `app/billing/page.tsx:7` uses `focus:outline-none` with no replacement ring.
Impact: Keyboard users get no visible focus on the page's only action. This fails WCAG 2.2 focus visibility. The shared `Button` already provides `focus-visible:ring-2`.
Fix: Replace the raw button with `<Button>`.
Verify: Tab to it and confirm a ring appears.

**[Must-fix] Imported modules do not exist in the project**
Evidence: `app/projects/page.tsx:2` imports `@/components/ui/card`, and `components/ui/button.tsx:3` imports `@/lib/utils`. A glob for `.tsx/.jsx/.vue/.svelte/.css/.scss/.html` found only `button.tsx` under `components/`. I did not search for `.ts` files or check `tsconfig` path aliases, so `@/lib/utils` could still exist as `lib/utils.ts`.
Impact: If `card.tsx` is really missing, `/projects` won't build. The `cn` helper may be fine.
Fix: Add `card.tsx`, or point the import at wherever it lives. Then confirm where `cn` resolves.
Verify: Run `next build`.

## Should-fix: design-system drift

The shared `Button` exists, but 4 of 5 call sites bypass it or override it. I found three separate styles for the same primary action.

| Location | Primary-action styling |
|---|---|
| `projects/page.tsx:9` | raw `<button>`, `bg-blue-600`, `rounded-xl`, `px-5 py-2.5` |
| `billing/page.tsx:7` | raw `<button>`, `bg-[#2563eb]` (hardcoded hex), `rounded-lg`, `px-4 py-2` |
| `settings/page.tsx:9` | raw `<button>`, `bg-red-500`, `rounded-full` |
| `button.tsx:10` | `bg-primary` (dark navy via the `--primary` token), `rounded-md` |

- **Colour:** Primary actions are blue in two places and dark navy in the third. Destructive red is `red-500` on settings but `--destructive` in `Button`. Use the tokens.
- **Radius:** `--radius` is 0.5rem, but the code uses `rounded-md`, `lg`, `xl`, `2xl`, `3xl` and `full` across the pages. Cards are `rounded-2xl` on projects and `rounded-3xl` on billing, and settings uses `rounded-lg`. Pick one card radius and one control radius.
- **Page chrome:** The three pages use different padding and title sizes.

| Page | Padding | Title |
|---|---|---|
| Projects | `p-6` | `text-2xl font-semibold` |
| Billing | `p-6` | `text-2xl font-semibold` |
| Settings | `p-8` | `text-3xl font-bold` |

  Settings should match the other two, or all three should share a `PageHeader` or layout component.
- **Surfaces:** Billing uses a hand-rolled `border p-6 shadow-lg` div. Projects uses `Card`. Settings uses a plain bordered `section`. Use `Card` everywhere.
- **Header layout:** `projects/page.tsx:7` has `flex justify-between` with no `items-center`, so the heading and button may misalign. Billing and Settings have no header action row at all.
- **Text colour:** `text-gray-500` on billing is a raw palette colour. Use a muted-foreground token.
- **Missing tokens:** `globals.css` defines only `--radius`, `--primary*` and `--destructive*`. `Button` also uses `ring`, `input`, `background`, `accent` and `accent-foreground`. Those are undefined here, so the focus ring and the outline and ghost hover states may not render. This is likely rather than confirmed, because I haven't seen the Tailwind config or any other CSS. `--primary` also looks like shadcn's HSL channel format, so `tailwind.config` needs to wrap it in `hsl()`.
- **Button API:** `button.tsx:23-25` is missing a `displayName` and an `asChild` or link variant. "Open" and "New project" are probably navigation, which would make them links, not buttons. `disabled:opacity-50` alone is a weak signal for disabled state.
