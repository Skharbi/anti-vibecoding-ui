## Must-fix

**Row actions are unreachable by keyboard and touch**
- Evidence: `filelist.css:3-4`. `.row-actions` is `display: none` and only becomes `display: flex` on `tr:hover`.
- Impact: `display: none` removes the buttons from the tab order and the accessibility tree. Keyboard and screen-reader users can't rename or delete anything. Touch devices have no hover, so they can't either.
- Fix: keep the actions in the DOM and hide them visually instead. Reveal them on hover with `:hover` and `:focus-within`, and always show them under `@media (hover: none)`. The simplest option is to show them always, perhaps muted until hover.
- Verify: Tab through a row and confirm both buttons receive visible focus. Emulate a touch device and confirm they appear.

## Should-fix

**Button names don't say which file they act on**
- Evidence: `FileList.tsx:12-13`. Every row has "Rename" and "Delete" with no file name.
- Impact: a screen-reader user listing buttons hears N identical "Delete" buttons.
- Fix: use `aria-label={`Delete ${f.name}`}`, or add visually hidden text such as `Delete <span class="sr-only">{f.name}</span>`.

**Delete has no visible protection against mistakes**
- Evidence: `FileList.tsx:13`. The click calls `onDelete(f.id)` directly.
- Status: needs verification. The parent may already confirm or offer undo, and I can't see it.
- Fix: if it doesn't, add a confirmation that names the file, or an undo toast. Style Delete as a destructive action and put some space between it and Rename.

**No empty state**
- Evidence: with `files=[]`, `FileList.tsx:7-17` renders a header over a blank body.
- Fix: render a row or message such as "No files yet", with an upload hint if that fits your flow.

**Table has no accessible name, and headers have no scope**
- Evidence: `FileList.tsx:5-6`.
- Fix: add a `<caption>` (can be visually hidden), or `aria-label` on the table. Add `scope="col"` to the `<th>` elements.

**`.sr-only` is incomplete**
- Evidence: `filelist.css:5`. It has no `white-space: nowrap` and no `margin: -1px`. The `position: absolute` also has no positioned ancestor.
- Impact: in some browsers this can cause odd text wrapping or stray scroll overflow.
- Fix: use the standard visually-hidden recipe, ideally a shared utility if the project has one.

## Needs verification

- **Long filenames:** `.files td` has no overflow rule. A long name could push the Actions column off-screen. Consider `overflow-wrap: anywhere`, or truncation with the full name in a `title`.
- **Narrow screens:** there is no strategy for narrow viewports. Check at about 360px, and consider hiding Size or stacking the actions.
- **Touch target size:** the buttons are unstyled defaults. Check that they reach roughly 24px or larger, the WCAG 2.2 AA minimum, with spacing between them.
- **Size column:** `size` is a pre-formatted string, so it can't be sorted numerically or right-aligned reliably. Fine if you don't need sorting.
