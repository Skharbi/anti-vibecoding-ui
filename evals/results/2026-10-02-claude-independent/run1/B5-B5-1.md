## Diagnostics: what's useful and what's missing

**Useful as written:** `message`, `stack`, `action`, `release`, and `ua`. These are enough to group errors by release and browser.

**Missing or weak:**
- **No HTTP status or error type.** `PaymentForm.tsx:5` folds the status into a string (`pay failed 402`), so you can't aggregate on it. Use a custom error class with `status` and `code` fields.
- **No server correlation.** Read a request or trace ID from the response headers and include it. That lets you join client reports to backend logs without logging any payload.
- **No timestamp, route name, or online/offline flag.** The ingest side may add a timestamp. Verify that.
- **`reportError` swallows its own failures.** The `fetch` is neither awaited nor given a `.catch`, so a blocked or failed ingest request produces an unhandled rejection. Add `.catch(() => {})`.
- **No sampling or rate limit.** A render loop that throws could flood the endpoint.
- **No request timeout and no idempotency key on `/api/pay`.** These are outside the logging scope, but a retry after a timeout could double-charge. Check how the backend handles duplicates.
