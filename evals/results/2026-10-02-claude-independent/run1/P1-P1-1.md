I couldn't open the MDN page, so this rests on the caniuse and web.dev search results.

Firefox "last 2 versions" is probably fine, but check that against current releases.
- Fix: Guard with `if ("navigation" in window)`. In the fallback, use `history.pushState` plus a `popstate` listener, or plain links to `?step=…`. Make the Continue button and the step render work without the Navigation API.

## Should-fix

- **No error or loading state.** The step is cleared (line 9) before the dynamic `import` (line 10). If the import fails or is slow, the user sees a blank area with a working Continue button. Render a loading state, catch errors with a retry message, and leave the old step in place until the new one is ready.
- **No handling of cancelled navigations.** A fast double-click or Back can leave an older import rendering over a newer step. Check `event.signal.aborted` after the `await`.
- **No check on what's being intercepted.** Add `event.canIntercept` and skip `event.downloadRequest`, hash-only changes, and cross-origin destinations before calling `intercept`.
- **Weak step wayfinding and a11y.**
  - There is no step indicator, such as an `<ol>` with `aria-current="step"`, and no "Step 2 of 4".
  - There is no per-step heading or `document.title` update, and no focus move or announcement. The Navigation API's default focus reset sends focus to the document body.
  - After a step change, move focus to the new step's heading, or use a polite live region.
- **Missing basics in `checkout.html`.** There's no viewport meta tag, so mobile layouts will be wrong. There's no `<noscript>` fallback and no CSS at all, so focus and touch-target sizes are browser defaults. There's also no Back button, so on mobile users depend on the browser Back gesture.
- **Step state across steps.** Nothing here keeps shipping or payment inputs when the user goes Back or reloads, because `innerHTML = ""` discards them. Whether this loses data depends on `steps/*.js`, which I couldn't see.
