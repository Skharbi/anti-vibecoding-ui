## Fix first: the Sign up button and "View terms" link are `<div>`s
**[Must-fix] Core actions can't be used by keyboard or assistive tech**
Evidence: `src/Signup.tsx:14-15` and `:21` use `<div onClick>` for "View terms", "Sign up", and "Close". `src/signup.css:4` also sets `outline: none` on `.cta`, `.link` and `input:focus`.
Impact: none of these controls can be reached with Tab, and Enter or Space won't activate them. A screen reader announces them as plain text, not as a button or link. A keyboard user can't submit the form or open the terms. Even if the divs got `tabindex`, the focus outline is removed, so focus would be invisible.
Fix:
- Make "Sign up" a `<button type="submit">` inside a `<form onSubmit>`. That also gives you Enter-to-submit.
- Make "View terms" and "Close" `<button type="button">` elements.
- Delete the `outline: none` rule and add a visible `:focus-visible` style.

## Then, in order

**[Must-fix] The terms modal has no dialog semantics or focus handling**
Evidence: `Signup.tsx:16-23` is a plain div pair with no `role="dialog"`, `aria-modal`, or label. Nothing moves focus in, traps it, handles Escape, or returns it on close.
Impact: keyboard focus stays behind the backdrop, so users can tab into the signup form while the modal covers it. There's also no way to dismiss it with Escape.
Fix: use native `<dialog>` with `showModal()`, which handles focus containment and Escape. Label it with `aria-labelledby`, and return focus to "View terms" on close.

**[Must-fix] The email field has no label association and the error isn't announced**
Evidence: `Signup.tsx:11-13`. The `<label>` has no `htmlFor` and the input has no `id`, `type`, `name`, or `autocomplete`. The error div has no link to the input.
Impact: screen readers announce an unnamed field. Mobile users get the wrong keyboard and no autofill. The "Enter a valid email" message is never announced.
Fix:
- Add `id`/`htmlFor`, `type="email"`, `name="email"`, and `autoComplete="email"`.
- Add `aria-invalid` and `aria-describedby` pointing at the error.
- Give the error `role="alert"`.
