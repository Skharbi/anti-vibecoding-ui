## Must-fix

**[Must-fix] Bulk delete is immediate, unguarded, and gives no feedback**
- Evidence: `UsersTable.tsx:19`. `onClick={() => deleteUsers(selected)}` runs with no confirmation, no check for an empty selection, no pending state, and no result handling.
- Impact:
  - One stray click permanently deletes users, possibly admins or the current user.
  - With nothing selected, it fires a pointless call.
  - `selected` is never cleared or refetched, so the UI can show deleted rows as still present. If the call fails, nothing tells the user.
- Fix:
  - Disable the button when `selected.length === 0`.
  - Make the label say what will happen, e.g. "Delete 3 users".
  - Add a confirmation dialog that names the count and says whether the action is reversible. Consider an undo or soft delete.
  - Show pending, success, and error states, and clear the selection on success.
- Verify: Select nothing and confirm the button is disabled. Select two rows and confirm the dialog appears. Force a failed request and confirm an error shows and the selection is kept.
- Server-side authorization for deleting users, and protection against deleting self or the last admin, needs verification. The UI can't enforce it.

**[Must-fix] Sortable headers are not keyboard- or screen-reader-operable**
- Evidence: `UsersTable.tsx:33-36`. These are `<div onClick>` elements with no role, no tabindex, no key handler, and no `aria-sort`. `table.css:2` only adds `cursor: pointer`.
- Impact: Keyboard and assistive-tech users can't sort at all. Sighted users also get no indicator of the current column or direction.
- Fix: Put a `<button>` inside each `<th>` and set `aria-sort="ascending|descending|none"` on the `<th>`. Show a direction icon plus text, not color alone.
- Verify: Tab to a header, press Enter or Space, and confirm the sort changes and is announced.

**[Must-fix] Pagination can go out of range**
- Evidence: `UsersTable.tsx:45-47`.
  - Prev is never disabled, so `page` can reach 0 or negative.
  - Next has no upper bound, though `total` and `pageSize: 25` are known.
- Impact: Users land on invalid pages, probably an empty or erroring table, with no way to see where they are.
- Fix:
  - Compute `pageCount = Math.ceil(total / 25)`.
  - Disable Prev at page 1 and Next at the last page.
  - Show "Page 2 of 7".
  - Wrap the pager in `<nav aria-label="Pagination">`.
- Verify: Click Prev on page 1 and click Next repeatedly. The page should stay in range.

**[Must-fix] Selection and page state go stale on filter, sort, and page changes**
- Evidence:
  - `UsersTable.tsx:13`, `:23`, `:26`, `:45`, `:47` change sort, filters, or page without resetting `page` or `selected`.
  - Select-all (`:32`) is uncontrolled and only selects the current page's rows.
- Impact:
  - Changing a filter while on page 5 can show an empty table.
  - Selected IDs from other pages or filters stay in state, so Delete can remove users who are no longer visible. This compounds the delete issue.
  - The select-all checkbox doesn't reflect the actual selection.
- Fix:
  - Reset `page` to 1 and clear `selected` when the filters or sort change.
  - Control the select-all checkbox, with an indeterminate state for partial selection.
  - Say "25 selected on this page" clearly.
- Verify: Select rows, change a filter, and confirm Delete only affects visible, selected rows.

**[Must-fix] Table semantics and control names are missing**
- Evidence:
  - `UsersTable.tsx:31-43` builds the table from `div` grids with no `table`, `th`, or `role` markup.
  - Row checkboxes (`:40`) have no accessible name.
  - The select-all text (`:32`) is not a `<label>`.
  - The role and status `<select>`s (`:23`, `:26`) have no label.
- Impact: Screen readers get no row or column relationships, and announce "checkbox" or "combo box" with no context.
- Fix:
  - Use `<table>`, `<thead>`, `<th scope="col">`, and `<tbody>`, with a caption or `aria-label`.
  - Add `aria-label={`Select ${r.name}`}` to each row checkbox.
  - Wrap the select-all checkbox in a `<label>` and add visible labels to the selects.
- Verify: Check with a screen reader or the accessibility tree.
