## Final output

I rewrote the modal so keyboard users can open it, operate it and close it. I haven't run it in a browser or with a screen reader, so none of it is tested yet.

**What was breaking it** (`src/ConfirmModal.tsx`, `src/modal.css`)
- **Fake buttons:** Cancel, Archive and ✕ were `div`/`span` elements with click handlers. They couldn't be reached with Tab and didn't respond to Enter or Space.
- **Hidden focus:** `outline: none` on `.btn` and `.close` would have hidden focus even if they had been reachable.
- **No focus management:** Focus stayed on the trigger when the modal opened. Tab moved through the page behind the overlay, and Escape did nothing.
- **No dialog semantics:** There was no dialog role or accessible name, and the title was a plain `div`.

**What I changed**
- **Native dialog:** The modal is now a `<dialog>` opened with `showModal()`. The browser handles focus trapping, Escape to close, making the page behind it inert, and returning focus to "Archive project" on close.
- **Real buttons:** Cancel, Archive and ✕ are now `<button type="button">`. The ✕ has `aria-label="Close"`.
- **Initial focus:** Focus starts on Cancel, the safe choice.
- **Labels:** The dialog is labelled by its title, which is now an `<h2>`, and described by the body text.
- **Mouse behaviour kept:** Clicking the backdrop still closes it.
- **Focus ring:** I replaced `outline: none` with a `:focus-visible` ring.
- **Small screens:** The dialog now fits narrow and short viewports. The old fixed 420px width could overflow them.
- **Styling:** The new `<button>`s needed small style additions (border, font, flex layout), so the buttons may look slightly different from before.

**To check**
- Tab/Shift+Tab should stay inside the dialog, Escape should close it, and focus should return to the trigger.
- Check it with a screen reader. The dialog should announce its title and description.
- If your tests or other code select `.overlay`, that class no longer exists. The dimmed background is now `.modal::backdrop`.
