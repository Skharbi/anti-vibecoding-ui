## Should-fix

**[Should-fix] Physical left/right utilities are used inside an RTL container**
Evidence:
- `text-left` on the link and heading (`:8`, `:11`) pushes them to the wrong edge.
- `mr-2` on the icon (`:9`) puts the gap on the outer side instead of between icon and text.
- `ml-4` on the paragraphs (`:12-14`) puts the indent on the wrong side.
- `pl-3 border-l-4` (`:17`) puts the accent border on the end side.

Fix: Use logical utilities: remove `text-left`, use `gap-2` or `me-2`, `ms-4`, `ps-3`, and `border-s-4`.

**[Should-fix] The date is in en-US format on an Arabic screen**
Evidence: `:13` uses `toLocaleDateString("en-US")`, which gives MM/DD/YYYY in Latin digits.
Fix: Use `Intl.DateTimeFormat("ar", { dateStyle: "medium", calendar: "gregory", numberingSystem: …, timeZone: … })` with every option set explicitly.
Judgment call: Whether to show Arabic-Indic or Latin digits, and which calendar, is a product decision. Make it deliberately.

Impact: The amount is always shown in dollars, and the `$` can be reordered by bidi rules. If your Arabic market uses another currency, this is wrong.
Fix: Add a currency code to the data and use `Intl.NumberFormat("ar", { style: "currency", currency })`.
Needs verification: Which currency the orders are actually in.
