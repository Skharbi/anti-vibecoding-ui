## Review: `Comment.tsx` and `CommentForm.tsx`

I read both files statically and didn't run them. This covers only these two components, not a full audit.

### Must-fix

**[Must-fix] Untrusted comment Markdown is rendered as unsanitized HTML**
Evidence: `src/Comment.tsx:6,10`. `marked.parse(comment.body)` goes straight into `dangerouslySetInnerHTML`. `marked` doesn't sanitize its output, and Markdown allows raw inline HTML. Comment bodies are user-authored by nature. I didn't check where `comment.body` comes from.
Impact: a body like `<img src=x onerror=...>` or a `[x](javascript:...)` link can run script in every viewer's session. That is stored XSS, with risk to sessions and account actions.
Fix: sanitize the parsed HTML with DOMPurify before injecting it. This is a real need, so the new dependency is justified. Restrict the allowed tags to what comments need (`p, em, strong, code, pre, ul, ol, li, blockquote, a`). Allow only `http`, `https` and `mailto` URLs, and add `rel="noopener noreferrer ugc"` to links. Server-side sanitization on write is the stronger control, and I couldn't verify whether it exists. Wrap the parse and sanitize step in `useMemo([comment.body])`.
Verify: render `<img src=x onerror=alert(1)>`, `<script>`, and `[a](javascript:alert(1))` as bodies. None should execute or keep the dangerous attribute or URL.

**[Must-fix] The form clears the textarea before the post is known to have succeeded**
Evidence: `src/CommentForm.tsx:5`. `onPost(body); setBody("")` runs unconditionally, and `onPost` returns `void`.
Impact: if the request fails, the user's comment is gone, with no error and no retry. This is data loss and misleading feedback.
Fix: make `onPost` return a `Promise`. Track `pending` and `error` state, and clear the field only after success. On failure, keep the text and show an error with `role="alert"`. Disable the submit button while pending, which also prevents double-posting.
Verify: make `onPost` reject. The text should stay, the error should be announced, and a retry should work.

### Should-fix

- **Empty and whitespace-only posts are accepted** (`CommentForm.tsx:5`). Guard on `body.trim()` and show a message when it's empty. Avoid a silently disabled button with no explanation.
- **The timestamp is a raw ISO string** (`Comment.tsx:9`), such as `2026-10-02T14:03:00Z`. Format it with `Intl.DateTimeFormat`, setting the timezone explicitly. Keep `dateTime` as the machine value.
- **Markdown headings can break the page outline** (`Comment.tsx:10`). A `# Title` in a comment renders an `<h1>` inside the article. Demote or disallow headings in the sanitizer config.
- **The textarea's `id` is `"c"`** (`CommentForm.tsx:6-7`). It's non-descriptive and collides if two forms render, such as in replies. Use `useId()`.
- **No success feedback and no focus handling after posting.** After a successful post, focus is left unmanaged and nothing confirms it. Add a polite status message or keep focus in the textarea.
- **The textarea has no `rows`, `name` or length limit** (`CommentForm.tsx:7`). Add `name`, a `maxLength`, and sensible sizing. A maximum length also needs a server-side limit.
- **The Markdown hint is not specific.** "Markdown supported" doesn't say which syntax works. Once the sanitizer allowlist is set, say what's allowed, for example "bold, italics, links, code".
