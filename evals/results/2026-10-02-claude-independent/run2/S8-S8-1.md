## Must-fix (confirmed in code)

**[Must-fix] Model output is rendered as raw HTML**
Evidence: `AssistantPanel.tsx:22` passes `reply.html` to `dangerouslySetInnerHTML` with no sanitization.
Impact: The model reads customer-authored tickets, so a ticket can carry an injected payload. If the model echoes it, script runs in the agent's session with `credentials: "include"`. Whether the server sanitizes `html` is unverified, but the client can't rely on that.
Fix: Have the API return structured text or Markdown and render it as React text nodes. If rich HTML is required, run it through DOMPurify with a tight allowlist.
Verify: Make the reply contain `<img src=x onerror=alert(1)>` and confirm nothing executes.

**[Must-fix] Model output can silently make authenticated API calls**
Evidence: `AssistantPanel.tsx:14` fetches whatever `url`, `method` and `body` the reply contains, with `credentials: "include"`. There is no confirmation, allowlist or error handling.
Impact: A prompt-injected ticket could trigger refunds or account changes with the agent's session, and the user is never asked. Given the README, this is the highest-impact path in the file. The server may enforce authorization and CSRF protection, but that needs verification. The UI should not be the one issuing arbitrary model-chosen requests.
Fix:
- Don't execute actions from the model reply.
- Return a typed proposal, such as `{ kind: "refund", ticketId, amount }`, and show it as a confirmation card with the consequence spelled out.
- Execute it only on an explicit click, against a fixed endpoint allowlist.
- Have the server re-authorize the action and check CSRF.
Verify: A reply with `call_api` to an arbitrary URL produces no request until the user confirms, and the request is rejected if it isn't on the allowlist.

**[Must-fix] Model-controlled navigation**
Evidence: `AssistantPanel.tsx:13` assigns `r.action.url` to `window.location.href` without validation.
Impact: This is an open redirect. It also allows `javascript:` URLs, which is an XSS vector, and it navigates away with no user action.
Fix: Don't auto-navigate. Render a link only if the URL parses as same-origin `https:` or is on an allowlist.
Verify: `javascript:`, `data:` and cross-origin URLs are rejected.

## Should-fix
