## Findings

**[Must-fix, needs a quick check] `Card` and `cn` imports resolve to files that don't exist**
Evidence: `app/projects/page.tsx:2` imports `@/components/ui/card`, and `components/ui/button.tsx:3` imports `@/lib/utils`. A glob of every ts/tsx/js file found neither. The only UI component is `button.tsx`.
Impact: if the files really aren't there, the build fails and the Projects page and `Button` can't render. They may live outside this directory or be mapped by a path alias I can't see, so I'm not calling it confirmed.
Fix: add `card.tsx` and `lib/utils.ts`, or correct the paths.
Verify: run `tsc` and `next build`.

**[Must-fix] Destructive action is styled and ordered unlike the rest of the app**
Evidence: `app/settings/page.tsx:9` is a raw `<button>` with `bg-red-500 rounded-full` and no focus style, and no `type` attribute. It bypasses `Button variant="destructive"`.
Impact:
- It has no visible keyboard focus ring, so a keyboard user can't see that they're on "Delete workspace".
- Nothing confirms the deletion.
- The two buttons have no spacing or grouping.
- `bg-red-500` with white text is roughly 3.8:1 contrast, below the 4.5:1 AA minimum for small text. This is my estimate, not a measured value.

Fix:
- Use `<Button variant="destructive">`.
- Add a confirmation step that names the workspace.
- Group the two buttons with `flex gap-2`.

Verify: tab to the button and check the focus ring and the confirm flow.

**[Must-fix] Raw `<button>` elements bypass the `Button` component and drop its focus ring**
Evidence:
- `app/projects/page.tsx:9`: `bg-blue-600 rounded-xl px-5 py-2.5`, no focus style.
- `app/settings/page.tsx:9`: the destructive button described above.
- `app/billing/page.tsx:7`: `bg-[#2563eb] rounded-lg`, plus `focus:outline-none`, which removes the focus indicator entirely.

Impact: all three primary actions are invisible to keyboard focus. That is a WCAG 2.4.7 focus-visible failure, and it is confirmed in the code.
Fix: replace each with `<Button>`. This also fixes the radius, colour and focus drift in one step.
Verify: tab through each page and confirm a ring shows.

**[Should-fix] Overrides on the shared components**

These are three card treatments (`rounded-2xl`, `rounded-3xl`, `rounded-lg`) for the same concept. Billing and Settings don't use `Card` at all. The `--radius` token exists, but it is bypassed everywhere.

**[Should-fix] Colours and tokens are only partly defined**
- `tailwind.config.ts` and `app/globals.css` define only `primary` and `destructive`. `button.tsx` uses `ring`, `input`, `background`, `accent`, `accent-foreground` and `border`, and none of them are defined. Those classes won't generate, so the outline and ghost variants and the focus ring probably render without their intended colours. This is likely rather than confirmed, because it depends on how Tailwind resolves them at build time.
- `text-gray-500` on `app/billing/page.tsx:6` is a raw palette colour and bypasses the token system. Its contrast on white is about 4.8:1, which is borderline.
- The config has no `content` array, so Tailwind may generate no classes at all. I'd confirm this first.

**[Should-fix] Smaller details**
- `button.tsx:15` repeats `rounded-md` inside the `sm` and `lg` sizes. The base class already sets it.
- `app/projects/page.tsx:7`: the header row uses `justify-between` without `items-center`, so the heading and button may sit misaligned.
- None of the buttons has a `type`.

## What already passes

- Headings use `h1` then `h2` in order, and the pages use semantic elements (`section`, `h1`/`h2`).

4. Extract a shared page shell with one padding and one `h1` style, and use `Card` on all three pages.
5. Add a confirmation dialog for "Delete workspace".
