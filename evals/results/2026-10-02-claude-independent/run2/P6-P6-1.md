# Review: `src/PatientSearch.tsx`

**Result: Fail.** There is one confirmed must-fix, a stale-results race in a wrong-patient-sensitive flow. I only read the code. I didn't run it, and there are no styles or parent usage in this file to review.

## Must-fix

**[Must-fix] Out-of-order responses can show results for the wrong query**
Evidence: `PatientSearch.tsx:9-14`. Each keystroke starts an unguarded `fetch`, and whichever response lands last calls `setHits`. Nothing aborts or sequences them.
Impact: Type "smith", and a slow response for "smi" can arrive after the one for "smith". The list then shows patients that don't match the input. In a clinical picker, a user can select the wrong patient. The same flow also has no empty-input guard against a late response: clearing the box sets `[]`, then a late response repopulates it.
Fix: Use an `AbortController` per request, aborting the previous one. Or compare against a request counter or the latest `q` before calling `setHits`. Debounce at the same time (see below).
Verify: Throttle the network in devtools and delay the earlier request. The list must always match the current input.

## Should-fix

**[Should-fix] No error handling on the request** (`:12-13`)
- Evidence: `r.ok` is never checked, and there is no `try/catch`. A network failure is confirmed to be an unhandled rejection that fails silently.
- Likely, not confirmed: if the API returns a non-array body on 401/500, `hits.map` throws and the component crashes. Check the API contract.
- Fix: Handle `!r.ok` and thrown errors. Show an error message with a retry. Clear or keep the old hits deliberately. Handle an expired session (401) explicitly.

**[Should-fix] Missing loading, no-results and async-status states** (`:20-24`)
- Evidence: the only output is the list. "Nothing found", "still searching" and "haven't typed" all render as nothing.
- Impact: A user can read an empty list as "this patient doesn't exist". Screen reader users get no announcement when results change.
- Fix: Add a visible state line such as "Searching…", "No patients match 'x'" or "N results". Put it in a polite `role="status"` region. Keep the region mounted so the announcements fire.

**[Should-fix] Request fires on every keystroke and on whitespace** (`:9-12`)
- Evidence: the only guard is `!value`, so `" "` triggers a search.
- Fix: Trim the query. Consider a minimum length. Debounce around 250 ms.

**[Should-fix] Picking a result gives no feedback** (`:22`)
- Evidence: `onPick(h)` is called, but the list and input are untouched.
- Impact: The user can't tell what was selected. Patient names and MRNs also stay on screen after the choice.
- Fix: Clear the results and show or set the selection. Return focus somewhere logical. The right behavior depends on the parent flow.

**[Should-fix] `<button>` has no `type="button"`** (`:22`)
- Evidence: the type is unset, so it defaults to `submit`.
- Impact: If this component is ever rendered inside a `<form>`, picking a result submits the form.
