## Must-fix

**[Must-fix] Permission check fails open**
Evidence: `ProjectSettings.tsx:11` has `.catch(() => setCanEdit(true))`. Line 9 calls `r.json()` without checking `r.ok`. A 401, 403 or 500 with a non-JSON body throws and lands in the same catch. A JSON error body leaves `p.canEdit` undefined, which is falsy and hides the button.
Impact: A network failure, timeout or unparseable error response shows the Delete button to a user who may not have edit rights.
Fix: Default to `false` on every failure, check `r.ok` before parsing, and show a distinct "couldn't verify permissions" state with a retry.
Verify: Force the permissions request to fail, return a 403 and return a 500 HTML body. The button must stay hidden in all three cases.
Note: Hiding the button is not authorization. Whether `DELETE /api/projects/:id` enforces permissions server-side needs verification, because it is outside this file.

**[Must-fix] Delete shows "deleted" before it succeeds, with no confirmation**
Evidence:
- `:15` calls `setDeleted(true)` before any request.
- `:19–20` return on success, but failures are swallowed by an empty `catch {}`.
- `:16–21` retry up to 3 times with no backoff, and after the last failure the function ends silently.
- `:28` fires directly on click, with no confirmation and no pending state.

Impact:
- If the request fails, the user sees "Project deleted." while the project still exists. This is misleading feedback on a destructive action.
- There is no way to retry from the UI, because the button is gone.
- A single misclick deletes the project.
- A double-click can send duplicate requests.

Fix:
- Add a confirmation step (a dialog or typed project name) that states the consequence.
- Use `pending`, `error` and `done` states, and set `done` only after `r.ok`.
- Disable the button while pending, show an error with a retry on failure, and drop or back off the blind retry loop.
- After success, navigate away or give the user a next step.

Verify: Make `DELETE` return 500 and confirm an error appears and the button stays available. Double-click and confirm only one request is sent.
