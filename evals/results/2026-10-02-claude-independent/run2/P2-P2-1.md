## Must-fix

**Row actions are unreachable by keyboard and unreliable on touch**
- Evidence: `src/filelist.css:3-4`. `.row-actions` is `display: none` and only becomes `display: flex` on `tr:hover`.
- Impact:
  - `display: none` removes the buttons from the tab order and the accessibility tree. Keyboard and screen-reader users can't rename or delete anything, because focus can't reach the buttons to trigger the reveal.
  - Touch devices have no real hover, so the actions are at best inconsistently available.
  - Mouse users also can't see which actions exist until they hover.
- Fix: keep the actions in the tab order and reveal them visually only. Either show them always, or use this pattern (and gate the hover rule on `@media (hover: hover)` so touch users always see them):
  ```css
  .row-actions { display: flex; gap: 8px; opacity: 0; }
  .files tr:hover .row-actions,
  .files tr:focus-within .row-actions { opacity: 1; }
  @media (hover: none) { .row-actions { opacity: 1; } }
  ```
- Verify: tab through the table and confirm each button gets focus and becomes visible. Then check on a touch device or emulation.

## Should-fix

**Every button has the same accessible name**
- Evidence: `src/FileList.tsx:12-13`. Every row has "Rename" and "Delete" buttons with identical names.
- Impact: in a screen reader's button list or when tabbing, users can't tell which file a button affects.
- Fix: `aria-label={`Rename ${f.name}`}` and `aria-label={`Delete ${f.name}`}`. The visible text stays at the start of the name, so it still satisfies label-in-name.

**Delete has no visible consequence control in this component (Needs verification)**
- Evidence: `src/FileList.tsx:13`. `onDelete(f.id)` fires on a single click.
- This is a verification item, not a defect. The parent may show a confirm dialog or offer undo, but I can't see it. If it doesn't, this becomes a destructive-action must-fix.
- Also: the Delete button looks identical to Rename. Consider separating or styling it as destructive.

**Missing states and table context**
- No empty state: with `files=[]` the user sees only a header row.
- No `<caption>` or `aria-label` naming the table.
- No loading or error state. This may belong to the parent component.

**Narrow-screen strategy**
- Evidence: `.files { width: 100% }`, with no wrapping or truncation rules.
- Long file names, three columns, and two side-by-side buttons are likely to overflow or squeeze at 320px. Needs verification at 320px.
- Consider `overflow-wrap: anywhere` on the name cell, or a stacked layout on mobile.

**`size` is a pre-formatted string**
- Evidence: `src/FileList.tsx:2`.
- Impact: the component can't sort by size or format it for the user's locale. This only matters if sorting is on the roadmap. If it is, pass the size as a number of bytes.
