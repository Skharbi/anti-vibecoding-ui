## Must-fix

**1. The session access token is sent to a third-party log endpoint.** (`src/errorReporting.ts:13`)
- `token: session?.accessToken` goes in the body of every error report POSTed to `https://logs.example-observability.io/ingest`.
- Anyone with access to that log store, or to its retention and backups, could replay the token to act as the user.
- Remove the field. If the backend needs to correlate errors with a session, send a non-secret session or request ID instead.

**2. Raw payment form values are sent in error reports.** (`src/PaymentForm.tsx:7`, `src/errorReporting.ts:12`)
- When `/api/pay` fails, `submitPayment` calls `reportError(e, { action, input: values })`.
- `values` holds `cardNumber`, `cvc`, and `amount`, and `reportError` forwards it unchanged as `input`.
- Card number plus CVC in a third-party log is a serious privacy problem. It may also bring PCI DSS scope questions, which I haven't verified.
- Payment failures are a normal event (declines, network errors), so this would fire often.
- Stop passing `input` here. Log only the action name and the HTTP status, plus non-sensitive fields such as `amount` if you really need them.
