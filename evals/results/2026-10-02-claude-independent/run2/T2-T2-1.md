**What was slow**
1. **`date_trunc('month', o.created_at) = ...`** wraps the column in a function, so no index on `created_at` could be used. The rewrite compares the raw column to a month range instead (`>= start of month AND < start of next month`). The meaning is the same, including the session time zone.
2. **Correlated subquery**, which ran once for every matching customer. It's now a single `GROUP BY customer_id` pass over this month's orders, joined to customers with a `LEFT JOIN`. Customers with no orders this month still appear, with a NULL total sorted last, as before.
3. **`lower(email) LIKE '%@acme.com'`** has a leading wildcard, so it can't use a normal index. Matching on `reverse(lower(email)) LIKE 'moc.emca@%'` turns the suffix match into a prefix match that an index can serve.
4. **Missing indexes.** The schema had none beyond the primary keys, and Postgres doesn't index foreign keys automatically.

**Indexes added**

CREATE INDEX customers_email_rev_idx ON customers (reverse(lower(email)) text_pattern_ops);

- The `orders` index covers the month scan and the aggregation, so it can be an index-only scan. That depends on the table being vacuumed regularly.
