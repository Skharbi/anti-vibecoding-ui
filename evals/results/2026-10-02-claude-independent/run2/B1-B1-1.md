## What was wrong and is now fixed

**Must-fix**
- **Login was unusable by keyboard or screen reader.** The "button" was a `<div onClick>` and there was no `<form>`, so Enter did nothing. The fields had only placeholders as labels. It's now a real form with labels, `autocomplete`, `required` and a submit button (`Login.tsx`).
- **Login failures were silent.** A wrong password or a 500 response would call `onLogin(undefined)` and store the string `"undefined"` as a token. Now it checks `r.ok` and the token, shows distinct messages for bad credentials, server errors and network errors, and shows a pending state.
- **Claiming a shift gave no feedback.** The response was ignored, so a failed claim looked like a successful one, and nothing stopped double-clicks. Now only one claim can run at a time. On success the shift leaves the list and a status message says so. A 409 gets an "already taken" message. Other failures get an error message, and a network failure warns that the claim may not have gone through (`SwapBoard.tsx`).
- **Expired sessions weren't handled.** A 401 now clears the token and returns to login. There was also no log-out at all, which matters on shared hospital workstations. I added a Log out button (`App.tsx`).
- **The board had no loading, error, or empty states.** A failed fetch left a blank page or crashed on `.map`. It now has all three states, with a Retry button on error. The fetch is aborted on unmount, and the payload is checked to be an array.
- **The 3-column × 320px grid forced horizontal scroll on phones.** Nurses will use this on phones. It's now a responsive grid that works at 320px.

**Should-fix**
- **Semantics:** the board is now a list with headings, `<time>` elements, and a `main` landmark.
- **Claim buttons:** each has a distinct accessible name.
- **Dates:** formatting is explicit and handles invalid values.
- **CSS:** buttons are at least 44px, focus rings are visible, and borders and text meet contrast. I removed an unused `useEffect` import.

## Decisions and checks that need you

1. **Token storage.** The token is still in `localStorage`, so any XSS can steal it. An httpOnly, SameSite cookie would be safer, but that needs backend changes, so I left it.
2. **API contract.** I added `Content-Type: application/json` to the login request, and I assume 401 means an expired session and 409 means an already-claimed shift. Please confirm these against the API.
3. **Authorization.** The server must enforce who may claim what. Examples are ward, qualifications, and maximum hours or rest-period rules. The client can't enforce any of that.
4. **Timezone.** Shifts display in the viewer's local timezone. If staff or devices can be in a different zone from the hospital, set the hospital's timezone explicitly.
5. **Claim confirmation.** I left the one-click claim, since a confirm step is a product choice. Consider confirm or undo, because a claim commits a person to a shift.
6. **Still missing:** a CSP and security headers (deployment), tests, a `package.json`, and a real build. Once there is a build, run type-check, lint, and an axe/keyboard pass, then check 320px, tablet, and desktop.
