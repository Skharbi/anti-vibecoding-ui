# Review: `PriorityQueue.tsx` and `queue.css`

**Result: Not verified.** I found no confirmed must-fix defect, but this was static review only. I didn't run the component, test keyboard focus, use a screen reader, or check narrow viewports. The two likely issues below (focus loss and the narrow-width layout) need that check before sign-off.

## Findings, highest impact first

**[Should-fix] Reordering gives no feedback unless the item reaches first place**
Evidence: `PriorityQueue.tsx:27`. The status text only ever reports `items[0]`.
Impact: A screen-reader user who moves an item from rank 5 to 4 hears nothing. Nothing says which item moved or where it is now. The text also stays the same on every update that leaves the first item unchanged.
Fix: Have the parent or the component announce the moved item, for example "Fix login bug moved to position 4 of 12". Track the previous order to detect the move.
Verify: Press "Move up" with NVDA/VoiceOver on a mid-list item and confirm the announcement.

**[Should-fix, Likely] Keyboard focus may be lost after "Move up"**
Evidence: `key={it.id}` (line 30) means React moves the existing `<li>` nodes instead of recreating them. Moving a DOM node with `insertBefore` can blur the element inside it in some browsers. I couldn't confirm this without running it.
Impact: A keyboard user pressing "Move up" repeatedly could lose their place and have to tab back in from the top.
Fix: After reorder, restore focus to the moved item's button by `data-id` if `document.activeElement` is `body`.
Verify: Tab to a button, press Enter several times, and check where focus lands each time.

**[Should-fix] All "Move up" buttons share the same accessible name**
Evidence: `PriorityQueue.tsx:34`.
Impact: In a screen reader's button list or when tabbing, every control reads "Move up" with no item context.
Fix: Use `aria-label={`Move up: ${it.title}`}`, or put the title in a visually hidden span inside the button. Keep the visible text "Move up" as part of the name.

**[Should-fix] The animation measures viewport-relative positions**
Evidence: `PriorityQueue.tsx:15-20`. `getBoundingClientRect().top` is stored and compared on the next render.
Impact:
- If the user scrolls between renders, every row looks "moved" and they all animate spuriously.
- If `items` updates while an animation is running, the measurement includes the in-flight transform, which causes a visible jump.
- Entries for removed items are never deleted from the map.

Fix: Store `el.offsetTop`, which is layout-based and unaffected by scroll or transform. Prune ids that are no longer present.
Verify: Scroll the page, then bump an item, and confirm only the affected rows animate.

**[Should-fix] The first item's button still offers "Move up"**
Evidence: `PriorityQueue.tsx:34` has no state for `i === 0`.
Impact: The control is enabled but can do nothing. This is a state-completeness gap.
Fix: Either hide or disable it, or use `aria-disabled` with an explanation if you want it to stay focusable. If `onBump` has different semantics, such as raising the score, the "Move up" label is misleading. I can't tell from this file.

**[Should-fix] Missing empty, pending, and error states**
Evidence: An empty `items` renders a bare `<ol>`. `onBump` returns `void`, so there is no way to show pending or failure.
Impact: An empty queue looks broken, and a failed bump gives no feedback.
Fix: Add an empty message ("No items to triage"). If `onBump` is async, guard against double-clicks and surface errors.

**[Should-fix, Likely] The layout may break at narrow widths with long titles**
Evidence: `queue.css:2`. The grid is `2ch 1fr auto auto` with no `min-width: 0` and no `overflow-wrap` on `.title`.
Impact: At 320px, a long unbroken title could push the score and button out of the row. A rank of 100 or more overflows the `2ch` column.
Fix: Add `min-width: 0` and `overflow-wrap: anywhere` to `.title`. At small widths, stack the score under the title or move it onto its own row.
Verify: Check at 320, 768, and desktop widths with a 120-character title.

**[Minor] List semantics, global CSS, and dead code**
- `list-style: none` (`queue.css:1`) can remove list semantics in Safari/VoiceOver. This is from memory and I haven't verified it. Consider `role="list"`. The visible rank span also duplicates the `<ol>` numbering.
- `.sr-only` and the `*` reduced-motion rule (`queue.css:5-6`) are global and sit in a component stylesheet. The rule only touches `scroll-behavior`, which this component never uses, so it does nothing here.
- Only `:focus-visible` is styled on the button. Hover and disabled styles are absent. A hard-coded `#0b57d0` and `#ddd` bypass any design tokens, if you have them.
