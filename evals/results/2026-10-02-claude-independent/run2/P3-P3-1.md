**[Must-fix] The page is blocked from search**
Evidence: `app/pricing/layout.tsx:2` sets `robots: { index: false, follow: false }`. The README says `/pricing` is public and "we want people to find through search."
Impact: Search engines are told to drop the page, which defeats its purpose. This looks like a leftover staging setting.
Fix: Remove the `robots` override, or set `index: true, follow: true`. Also confirm that `robots.txt` and any `X-Robots-Tag` header at the host or CDN don't block it.
Verify: Check the built HTML for `<meta name="robots">` and the response headers.

**[Must-fix] The nav links can't be used from a keyboard or by assistive tech**
Evidence: `page.tsx:13-15` uses `<span className="navlink" onClick={() => router.push(...)}>`.
Impact: Spans can't be focused or activated with the keyboard, and screen readers don't announce them as links. You also can't open them in a new tab or copy the URL, and crawlers can't follow them. The same markup hurts SEO and accessibility (WCAG 2.1.1 and 4.1.2).
Fix: Use `<Link href="/features">` from `next/link` for each one. Put the links in a `<nav aria-label="Primary">` inside a `<header>`, and keep a visible focus style.
Verify: Tab through the page and press Enter on each link. Middle-click should open a new tab.

**[Must-fix] Plans are fetched in the browser, and failure is silent**
Evidence: `page.tsx:1,8`. This is a client component that fetches `/api/plans` in `useEffect`, starting from `[]`. There is no `res.ok` check, no `.catch`, and no loading state.
Impact:
- The first HTML contains only the "Pricing" heading and no plans. This is confirmed from the code. How much it hurts indexing depends on how Google renders the page, which I haven't tested.
- If the request fails or returns non-JSON, the page stays blank with no message, or throws an unhandled rejection. Visitors see an empty pricing page.

Fix:
- Fetch the plans in a server component, with `revalidate` caching or a static source. Keep client code only where it's needed.
- Add an error state with a retry link and a loading skeleton if any client fetch remains.
- Render a fallback such as "Pricing is temporarily unavailable. Contact us."
