## Must-fix (confirmed in code)

**[Must-fix] Analytics script loads before any consent choice**
Evidence: `src/ConsentBanner.tsx:6` runs `loadAnalytics()` in a mount effect with no check of the stored choice. `src/trackers.ts:1` injects the GTM script.
Impact: Every visitor's request goes to Google on page load, before they can respond to the banner. Consent is meant to come before non-essential tracking. Whether GTM sets cookies or processes personal data is not verified here, but the request is made either way.
Fix: Call `loadAnalytics()` only after a stored choice that includes analytics.
Verify: In a fresh profile, check the Network tab. No `googletagmanager.com` request should appear until the user accepts.

**[Must-fix] No way to refuse, and no real preference controls**
Evidence: `ConsentBanner.tsx:11-12` offers one prominent "Accept all" button. The only other option is "Manage preferences", which is a link to `/privacy` rather than a control.
Impact: Accepting takes one click, while refusing or choosing categories means leaving the page. The wording "By continuing to browse you agree" (`:10`) frames scrolling or browsing as consent. Regulators generally don't accept that as valid consent.
Fix: Add an equally prominent "Reject all" button and a preferences dialog with separate analytics and advertising toggles that are off by default. Reword the text to name the purposes, and remove the "by continuing" language.
Verify: Reject and accept each take one click, and no optional script loads after rejecting.

**[Must-fix] Consent is stored as a single value, with no record or way to withdraw it**
Evidence: `ConsentBanner.tsx:11` writes `localStorage "consent" = "all"`. Nothing in `src/` reads or changes the value afterwards, and a refusal isn't stored at all.
Impact: Users can't change their mind later. Withdrawing consent should be as easy as giving it. There is also no record of the version, timestamp, or purposes consented to.
Fix: Store `{version, timestamp, categories}`. Add a persistent "Cookie settings" entry point, for example in the footer, that reopens the preferences.
Verify: Accept, then withdraw. Ad and analytics scripts should stop loading on the next page load.

**[Must-fix] Initial state and shown ad loading disagree**
Evidence: `ConsentBanner.tsx:5` checks only whether `"consent"` exists. `:6` loads analytics regardless of that value.
Impact: The ads script is gated by the click handler, but it is not reloaded on later visits, so the ad behavior is inconsistent. Analytics ignores the stored state entirely.
Fix: Derive loading from the stored categories on mount, in one place.

## Should-fix

- **Contrast:** The "Manage preferences" link at `banner.css:3` is `#666` on `#111`, which I calculate at about 3.3:1. It is also 11px. This fails WCAG 1.4.3 (4.5:1), and the choice is visually de-emphasized (a dark pattern). The white text on `#22c55e` at `banner.css:2` comes to about 2.3:1, which also fails.
- **Link vs. control:** The preferences option should be a real button of equal weight, not a small link that navigates away.
- **Layout and a11y:**
  - A fixed bar with no wrapping can cover page content and wraps badly at 320px.
  - `role="region"` is acceptable, but nothing manages focus. That is fine for a non-modal bar, but keyboard users get no path to it.
  - There is no focus style.
- **Robustness:** `localStorage` is read during render (`:5`). This throws when storage is blocked and breaks SSR.
