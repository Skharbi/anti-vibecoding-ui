## Final output

I rebuilt the modal in `src/ConfirmModal.tsx` and `src/modal.css` on a native `<dialog>`, so the browser now handles focus. I haven't run it in a browser or with a screen reader, so none of this is tested.

**What was broken**
- The buttons and close icon were `div`/`span` elements with click handlers. Keyboard users couldn't reach or activate them.
- `outline: none` removed the focus ring from the controls.
- There was no `role="dialog"`, no accessible name, no Escape handling, no focus move into the dialog, no focus trap and no focus return. The page behind stayed interactive.

**What changed**
- `showModal()` makes the dialog modal. That traps Tab inside it, makes the background inert and closes it on Escape. It also returns focus to the "Archive project" trigger on close.
- Cancel gets focus when the dialog opens. I chose Cancel because Archive is a consequential action, so pressing Enter by accident does nothing harmful.
- The dialog stays mounted and is opened and closed in an effect. That is what lets the browser restore focus.
- `onClose` keeps React state in sync when Escape closes the dialog.
- Clicking the backdrop still closes it.
- The title is now an `<h2>` and is the dialog's accessible name. The description is linked with `aria-describedby`.
- Cancel, Archive and the ✕ are real `<button type="button">` elements. The ✕ has `aria-label="Close"`.
- The focus ring is back, using `:focus-visible` with a 2px outline.
- The dialog width is now `min(420px, 100vw - 32px)` with a max height and scroll, so it fits narrow and short screens.
- `.btn` got a border and `font: inherit`, so the buttons read as buttons now that they are native.

**Left alone**
- The modal's visual style, the copy, and the `onArchive` behavior.

Before shipping, please test it with Tab/Shift+Tab, Escape and a screen reader. This relies on native `<dialog>`, which is supported in current browsers.
