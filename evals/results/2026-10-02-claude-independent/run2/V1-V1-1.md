## Findings

**[Should-fix] Empty state is a dead end**
- Evidence: `index.html:1`, `<p>No items.</p>` is the only content.
- Impact: The user can't tell what an "item" is. They also can't create or import one, and can't tell whether the list is empty or hasn't loaded or failed.
- Fix: Name the actual entity, say why the list is empty, and add the primary next action. Keep the empty state separate from loading and error states.
- Verify: Render each of empty, loading, error and populated, and confirm each one is distinguishable.

**[Should-fix] Generic title and heading ("Items")**
- Evidence: `index.html:1`, `<title>Items</title>` and `<h1>Items</h1>`.
- Impact: The browser tab, history and screen-reader page announcement don't identify the product or screen. The page could belong to any product.
- Fix: Use a product-specific title, such as "Screen name – Product". This depends on product context I don't have.
- Verify: Check the tab title and the heading.

**[Should-fix] No `<meta charset>`**
- Evidence: `index.html:1` has none. I can't see the server's `Content-Type` header.
- Impact: There's no effect today because the content is ASCII. Any non-ASCII text added later could be mis-decoded if the server doesn't declare a charset.
- Fix: Add `<meta charset="utf-8">` as the first element in the head.

**[Judgment call] Viewport meta lacks `initial-scale=1`**
- Evidence: `width=device-width` only.
- Impact: Modern browsers handle this fine. It's a minor consistency point, and it's worth keeping zoom unrestricted.
- Fix: Optionally use `width=device-width, initial-scale=1`. Never add `user-scalable=no` or `maximum-scale`.
