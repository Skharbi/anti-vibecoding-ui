## Must-fix

**1. Every patient's full health record is sent to a third-party analytics service**
- **Where:** `src/IntakeForm.tsx:12` calls `analytics.track("intake_submitted", { ...v, ts })`. `src/analytics.ts:3` sends that to `https://collect.example-analytics.io/v1/e`.
- **What leaks:** the entire form — name, date of birth, phone, national ID, insurance number, symptoms, medications and pregnancy status — plus the page URL.
- **Why the timing makes it worse:** it's sent *before* `onSubmit`. The data leaves the browser even if the real submission fails, and `sendBeacon` can't be recalled.
- **Legal status:** I can't say from the code whether this breaks HIPAA, GDPR or any other rule. That depends on where you operate and on any agreement with the analytics vendor. As written, though, it's a high-impact exposure of health data.
- **Fix:** send only the event name, and something like `{ ok: true | false }` after the submit settles. Never spread form values into telemetry. Also check whether `location.href` could contain identifiers.
- **Verify:** in DevTools → Network, submit the form. The request to `collect.example-analytics.io` should contain no form values.

**2. Submitting gives no feedback and can create duplicate records**
- **Where:** `src/IntakeForm.tsx:10-14`, `:26`.
- **What happens:**
  - If `onSubmit` fails, nothing catches the error. The patient sees nothing and doesn't know their intake wasn't received.
  - If it succeeds, they also see nothing.
  - The button stays active while the request is running, so a second click or Enter press sends it again. For patient records, that means duplicates.
- **Fix:**
  - Track the state (`idle | submitting | error | success`) and disable the button while submitting, with "Submitting…" as its label.
  - Show a readable error with a retry option, announced with `role="alert"`.
  - Show a clear confirmation on success, such as what happens next.
  - The typed values are already kept on failure; keep it that way.
- **Verify:** make `onSubmit` throw, and make it hang. Check that the error shows, the button is disabled while pending, and double-clicking doesn't send twice.

## Should-fix

3. **There's no validation or required fields (`:18-25`).** An empty form can be submitted. Mark the fields that are truly required (`required`, plus a visible marker). Tie errors to fields with `aria-describedby` and `aria-invalid`. Add `max={today}` on date of birth. The server still has to validate; I couldn't check that it does.
4. **Pregnancy status is a free-text box (`:25`).** Answers like "no", "n/a", "maybe" or "12 wks" can't be used reliably in a clinical setting. Use radio buttons in a `<fieldset>`/`<legend>` with explicit options (Yes / No / Not sure / Prefer not to say). Consider showing it only when relevant.
5. **The form never says what it's for or how the data is used.** There's no heading, no purpose line and no privacy or consent notice, which matters for health data. Add a heading, a short "who sees this" note, and help text on the symptoms and medications fields (for example, "include dose and how often").
6. **It asks for sensitive IDs without a stated reason.** Is the national ID actually needed at intake? If it is, add `inputMode`/`spellCheck={false}` and a format hint to the ID and insurance fields. If not, drop it. This is a product decision you'll need to make.
7. **There's no layout structure (`:18-25`).** Labels and inputs are loose siblings with no wrappers, so without CSS (and there's none in the repo) they'll run together on one line. Wrap each pair in a field container. I couldn't check how it looks on phones.
8. **Minor:** `setV({ ...v, ... })` (`:8`) reads a possibly outdated copy of the form state; `setV(prev => ({ ...prev, [k]: ... }))` is safer.

## What already works
- Every field has a real `<label htmlFor>`, so screen readers can identify each one.
- It uses a proper `<form>`, `type="submit"`, and suitable `type`/`autoComplete` values for name, date of birth and phone.
- It uses native controls only, with no ARIA misuse.
- Entered values are kept after a failed submission.
