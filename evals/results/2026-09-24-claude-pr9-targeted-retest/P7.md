## Must-fix

**1. Switching accounts shows the wrong account's invoices**
- **Where:** `src/useInvoices.ts:3`, `:6`, `:8` and `src/AccountSwitcher.tsx:4-5`.
- **What happens:** `cache` sits at the top level of the module and uses the fixed key `"invoices"`, with nothing about the account in it. The switcher changes page with `pushState` and a fake `popstate` event, so the page never reloads and the cache survives. When `/billing` mounts again, `useState(cache.get("invoices"))` starts with account A's data, and `if (cache.has("invoices")) return;` means it never fetches account B's. Nothing clears the cache, so this lasts until a full page reload. The same thing would happen if someone logs out and a different person logs in on the same tab without a reload.
- **Impact:** the user sees account A's invoices under account B. At best that's wrong financial information. If the two accounts belong to different organisations, it shows one organisation's billing to the other.
- **Fix:** include the account in the cache key, clear the cache when the account switches or the user logs out, and fetch again when the account changes (add the account to the effect's dependency list). If the app already uses a data library such as React Query or SWR, use it and call `queryClient.clear()` on switch. Simplest option: after a switch, do `location.assign("/billing")` instead of the `pushState` workaround.
- **How to check:** switch A→B→A and confirm each account's invoices appear. Watch the Network panel for a new `/api/me/invoices` request after each switch.

**2. The switcher ignores a failed switch**
- **Where:** `src/AccountSwitcher.tsx:3-5`.
- **What happens:** `fetch` only rejects on network errors. A 401, 403 or 500 response still resolves, and the code goes on to open `/billing` as if the switch worked. If the network fails, the rejection goes unhandled and the user sees nothing.
- **Fix:** check `res.ok`. Only navigate and clear the cache when it succeeds. Otherwise show an error, e.g. "Couldn't switch to {name}", in an `aria-live`/`role="alert"` region.

**3. The request body is sent as `text/plain`, not JSON**
- **Where:** `src/AccountSwitcher.tsx:3`.
- **What happens:** when the body is a string, `fetch` labels it `Content-Type: text/plain;charset=UTF-8`. A server expecting JSON (Express `json()`, most frameworks) will read an empty body, and the switch fails. Combined with finding 2, the failure gives no feedback.
- **Fix:** add `headers: { "Content-Type": "application/json" }`.
- **To check with the backend:** this is a cookie-authenticated POST sent as a "simple" request, so the browser doesn't run a CORS preflight. Confirm the server has CSRF protection (a token, an Origin check, or SameSite cookies) and that it refuses `text/plain`. I can't confirm that from the frontend code.

## Should-fix

**4. `useInvoices` can't report loading or errors**
- **Where:** `src/useInvoices.ts:9`.
- **Problems:**
  - It never checks `r.ok`, so an error response body such as `{error:"Unauthorized"}` is cached permanently as the invoice data.
  - It has no `.catch`, so a network failure leaves `data` as `undefined` forever.
  - `undefined` means both "loading" and "failed", so the UI can't tell them apart or offer a retry.
- **Fix:** return `{ data, error, status }`. Only cache responses that succeeded. Expose a `refetch` function.

**5. Responses can arrive late or be requested twice**
- **Where:** `src/useInvoices.ts:7-10`.
- **Problems:**
  - Nothing cancels a request, so a response for the old account that arrives after a switch still gets stored.
  - Two components mounting at once both fetch, because the cache is only filled after a response arrives.
- **Fix:** use an `AbortController` in the effect cleanup, and store the in-flight promise in the cache rather than only the result.

**6. The switcher has no pending state or current-account marker**
- **Where:** `src/AccountSwitcher.tsx:8`.
- **Problems:**
  - Nothing happens on screen during the request, and double-clicking or clicking two accounts quickly sends competing switches.
  - Nothing shows which account is active.
- **Fix:** disable the buttons while a switch is pending (native `disabled`) and show that it's in progress. Pass `currentId` in and mark the active button with `aria-current="true"`.

**7. Navigation goes around the router**
- **Where:** `src/AccountSwitcher.tsx:4-5`.
- **What happens:** a hand-made `popstate` event only works if the router listens for it. Focus also isn't moved after the page changes.
- **Fix:** use the app's router `navigate()`, or a full reload (see finding 1).
- **To check:** I couldn't see a router in the repo. Only these two files exist.

## Suggested shape of the fix
```ts
// useInvoices.ts
const cache = new Map<string, Promise<Invoice[]>>();
export const clearInvoiceCache = () => cache.clear();

export function useInvoices(accountId: string) {
  const [state, setState] = useState<{ data?: Invoice[]; error?: Error }>({});
  useEffect(() => {
    let live = true;
    setState({});
    let p = cache.get(accountId);
    if (!p) {
      p = fetch("/api/me/invoices", { credentials: "include" }).then((r) => {
        if (!r.ok) throw new Error(`HTTP ${r.status}`);
        return r.json();
      });
      p.catch(() => cache.delete(accountId)); // don't cache failures
      cache.set(accountId, p);
    }
    p.then((data) => live && setState({ data }), (error) => live && setState({ error }));
    return () => { live = false; };
  }, [accountId]);
  return state;
}
```
