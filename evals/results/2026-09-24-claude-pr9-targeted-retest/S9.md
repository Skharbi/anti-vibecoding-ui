## Must fix (confirmed)

**1. The lockfile is empty.**
`package-lock.json:1` lists only the root package: `"packages": { "": {...} }`. It has no resolved versions and no integrity hashes.
- **What happens:** `npm install` picks versions fresh on every machine and every build, so you can't reproduce or audit what ships. Integrity hashes pin the exact package contents, and there are none. `npm ci` will likely refuse to run because the lockfile doesn't match `package.json`.
- **Why it matters:** caret ranges like `^3.6.0` (`package.json:9-14`) will pull in whatever new minor or patch release comes out, including a hijacked one. This is the "software supply chain failures" risk in the OWASP Top 10:2025.
- **Fix:** run `npm install` in a trusted environment, commit the full lockfile, and use `npm ci` in CI and deploys.
- **Check:** the lockfile has `resolved` and `integrity` entries for every package, and `npm ci` succeeds on a clean checkout.
