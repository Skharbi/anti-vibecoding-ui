**1. The main button's label gets cut off**
Evidence: `src/OrderDetails.tsx:24`: `w-32 whitespace-nowrap overflow-hidden` with `locales/ar.json:8` "طلب إرجاع المنتجات واسترداد المبلغ" (34 characters).

Fix: Remove the fixed width, `whitespace-nowrap` and `overflow-hidden`, and use `min-w-*` or padding instead. Also shorten the text to "طلب إرجاع" ("Request return"); the refund detail can go in the confirmation step.
Verify: Render it at 360px wide. The full label should be visible.

**2. Arrows and chevrons point the wrong way**
Evidence: `:9` uses `ArrowLeft` for "back"; `:20` uses `ChevronRight` on each row.
Impact: In Arabic the page reads right to left, so "back" should point right and "forward" should point left. As written, the back link shows a "forward" arrow.
Fix: Use `ArrowRight` for back and `ChevronLeft` on rows when the page is right-to-left, or flip both with `rtl:-scale-x-100`.

**3. Left/right CSS classes fight the right-to-left layout**
Evidence:
- `text-left` at `:8` and `:11`: the heading is pinned to the left while the rest of the text starts on the right.
- `mr-2` at `:9`: the icon sits on the right in this layout, so the gap lands on its outer edge instead of between the icon and the text.
- `ml-4` at `:12–14`
- `pl-3 border-l-4` at `:17`: the accent bar ends up at the end of each row instead of the start.

Fix: Swap in the direction-aware versions: `text-start`, `me-2`, `ms-4`, `ps-3`, `border-s-4`. You could also replace the icon margin with `gap-2` on the flex container.

**4. The date shows in US format**
Evidence: `:13`: `toLocaleDateString("en-US")`.
Impact: An Arabic screen shows "9/24/2026", which reads month-first and is ambiguous for most Arabic-speaking users.
Fix: Use `Intl.DateTimeFormat("ar", { dateStyle: "long", calendar: "gregory", numberingSystem: "latn" | "arab", timeZone: … })`. Set the calendar, digit style and time zone on purpose rather than relying on browser defaults. Which calendar and digits to use is a product decision; see the open questions below.
Needs checking: if `placedAt` is a date without a time (e.g. `"2026-09-24"`), `new Date()` treats it as midnight UTC. Users in time zones behind UTC would then see the previous day.

**5. The currency symbol is hardcoded**
Evidence: `:14`: `` `$${order.total.toFixed(2)}` ``. The `Order` type (`:3`) has no currency field.
Impact: Every total shows in dollars with US formatting. If Arabic-speaking customers pay in SAR, AED, EGP or another currency, the screen shows the wrong amount.
Fix: Add a `currency` field to the order data and use `Intl.NumberFormat("ar", { style: "currency", currency: order.currency })`.

**6. Arabic plurals are wrong for most quantities**
Evidence: `:19`: `{i.qty} {t("items")}` with `"items": "قطع"`.
Impact: Arabic has six plural forms. "قطع" is only correct for 3–10. It's wrong for 1 ("قطعة واحدة"), 2 ("قطعتان"), 11 and up ("قطعة"), and 0.
Fix: Use ICU plural messages in the translation file, e.g. `{count, plural, zero{…} one{قطعة واحدة} two{قطعتان} few{# قطع} many{# قطعة} other{# قطعة}}`, or pick the form with `Intl.PluralRules("ar")`.

## Should-fix

- **Mixed-direction text can display in the wrong order** (`:11`, `:12`). Order IDs like `ORD-2026-0042` and customer names in Latin script sit inside right-to-left text, and punctuation next to them can jump to the wrong side. Wrap each in `<bdi>`.
- **The chevron looks clickable but isn't** (`:17–21`). The `<li>` isn't a link and has no handler. Either make each row a real link to the item or remove the chevron.
- **The button does nothing** (`:24`). There's no `onClick` and no `type`. A return/refund request needs a confirmation step, a pending state, and a disabled state with a reason when the order isn't eligible. I can't see any of that from here, so it needs checking in the actual flow.
- **Duplicate list keys** (`:17`). `key={i.name}` breaks if the same product appears twice (e.g. two sizes). Use an item or line ID.
- **Label/value pairs use `<p>`** (`:12–14`). A `<dl>` with `<dt>`/`<dd>` tells screen readers which text is the label and which is the value.
- **Language and direction are hardcoded in the component** (`:7`). `t` is passed in but `dir="rtl" lang="ar"` isn't, so this is effectively a separate Arabic copy of the screen. Set `lang` and `dir` on `<html>` from the current language and keep one shared component; otherwise the English and Arabic versions will drift apart.
- **Only the normal case is handled.** There's nothing for an order with no items, a missing date, or a long item name.
